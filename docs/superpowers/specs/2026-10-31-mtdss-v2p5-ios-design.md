# MTDSS V2-P5 iOS 客户端 设计稿

日期:2026-10-31 | 状态:待 builder 评审 → 待用户批准
来源:2026-10-30/31 brainstorm(含六轮视觉 mockup 定稿),决策人为用户本人,记录人为 Claude。

## 1. 意图与背景

V2 五阶段的收官项目:为首批真实用户中占比约半数的 iPhone 用户交付原生 iOS 客户端。引擎与产品语义已在 V2-P1(中继)、P2(跨会话任务)、P3/P4a(安卓客户端+收件暂存)全部落地并实盘验证;P5 只需把已验证的引擎形态搬进 iOS 进程模型,产品语义原样承接。

前置条件(均已就绪):Apple 开发者账号(个人)已批;Mac mini(Apple Silicon,兼构建机)在位;`mtdss.top` 域名与 VPS 产线在役。

**为什么现在**:P4b 已收官、打包轮 1.1.0 物料全备,Windows/安卓/服务端三线齐备,iOS 是最后一块;账号审批这一纯前置时间已消化。

## 2. 目标 / 非目标 / 反目标

**目标(v1)**:
- 功能面对齐安卓 v1:登录、设备互见、浏览远端、双向收发、任务列表/中断重发、系统分享入口
- TestFlight 外部组内测先行,首批用户即装即用
- UI 达到"苹果原生精品"水准(本轮用户钦定为一等目标,安卓 v1 的"能用薄壳"教训不重演)

**非目标(v1 明确不做)**:
- App Store 公开上架(后续里程碑;涉及评审与卖家名展示策略)
- App 内自更新(商店/TestFlight 接管更新;iOS 也不允许自更新)
- 平铺/网格视图(用户裁定"先不做页面模式切换",全 App 仅列表态;票留后续版本)
- 扫码登录(我的页左上角放图标占位)、常用目录管理(首页只保留收件箱一枚)、联系我们/为我打分/我的权益(占位页)
- 静默推送后台自动发送(APNs 基建,票 C → v1.x)、分享扩展内小文件直发(性价比低,否决)
- iPad 适配、横屏、watchOS、Live Activity、推送通知、多语言(中文单语)

**反目标**:
- 任何"桌面范式"的移植:信息密度、行高、控件尺寸必须按 iOS 触控习惯重做(用户在 mockup 轮对 30px 行高桌面列表明确否决)
- 自绘主题系统/品牌脸移植(用户在 A/B/C 三方向中明确选择 A:纯原生 HIG,理由"看着习惯、不花里胡哨")
- 引擎重写或 Swift 直译引擎:必须复用 Rust 引擎(零 FFI 大改,同安卓路线)

## 3. 产品语义(承接安卓已裁定,逐条平移)

| 语义 | 内容 |
|---|---|
| 前台=在线 | 无常驻、无后台保活;切后台/熄屏,传输死活随系统(短窗口内断,标「中断」) |
| 不自动续传 | 任务列表是一等界面;中断后手动「重新发起」(P2 语义:翻新同记录换新 job_id,有续传基础则续传) |
| 收件 = 私有暂存+完成发布 | P4a 语义:iOS 形态=收件中文件落 App 私有 `.mtdss` 暂存区,完成后 move+rename 发布进收件箱;杀 App 中间态不可见 |
| 收件箱 | 每端默认收件目录;iOS=App Documents(开 UIFileSharingEnabled/LSSupportsOpeningDocumentsInPlace,文件 App 可见);默认对其他设备可见可浏览。(2026-11-03 R8 终审 M-d 注:「不可删除」已随 R5b 远端删除演进——对端可删授权根内文件(走既有 ctrl delete 契约,UI 恒确认);收件箱根目录自身被删不自卫,自愈=下次收件照常重建落位;根目录自身的删除拒收入票,见 §10) |
| 发送免选目录 | 发送给任意设备默认落对方收件箱——移动端减一跳(用户钦定产品原则) |
| 发送/转发/下载 | 发送=本机→远端收件箱(常用目录页操作);转发=远端A→远端B 调度(设备页浏览 A 时操作);下载=远端→本机收件箱 |
| 授权目录集(2026-10-31 用户定案;2026-11-01 Ruling N 真机修订) | 授权集 = **收件箱(默认,首页唯一展示项)+ 信任目录(白名单,仅设置页管理,不出现在首页)**;授权集内引擎可读 → ①其他设备可浏览进来 ②可作发送授权。**发送路径 = 收件箱浏览多选 + 系统分享扩展**;App 内文件选择器直发不做。信任目录=引擎出站白名单+发送授权,授权/移除入口只在设置页 |
| 信任目录 | 出站白名单+发送授权(≈安卓 SAF 授权根;iOS 用安全域书签实现);管理入口在设置页,「+」开系统目录选择器选定即授权 |
| 备份策略(用户裁定) | 收件箱是系统真实目录,**不干预备份**(isExcludedFromBackup 不设,用户自己在 iCloud 备份里选);暂存区 `.mtdss` 与分享队列属 App 内部中间态,排除备份 |
| 隐藏项 | 浏览时默认隐藏对端隐藏目录/文件,设置有开关,只影响显示不影响传输 |
- 传输完成 | 发本地通知(无推送)

**发行前置物料**:TestFlight 外部组需隐私政策 URL——记录人起草(涉及邮箱/设备名/中继元数据表述)→**用户过目**→挂 `mtdss.top/privacy` 静态页(2026-10-31 用户定案);App 图标 v1 用简洁占位(记录人出),品牌资产留票;出口合规按标准加密豁免惯例勾选。

## 4. UI 设计语言(2026-10-31 定稿,mockup 全存档)

**总范式**:苹果原生 HIG,白底极简扁平,跟系统深浅,系统蓝,iOS 26 Liquid Glass 时代控件。四标签 + 悬浮玻璃胶囊标签栏。**零自绘主题系统**(工程红利:不建 token 体系)。

**设计基准**:440×956pt(用户测试机 iPhone 16 Pro Max 2868×1320÷3);字号行高按系统规格(大标题 34 / 正文 17 / 列表行 56-64 / 副文 12.5-13)。

### 4.1 浏览页模板(收件箱/远端浏览共用)

> 注(2026-11-01 Ruling N 真机修订):信任目录不再出现在首页/常用目录,浏览页模板的信任目录档撤销;授权集=收件箱(默认,首页唯一展示项)+信任目录(白名单,仅设置页管理,不出现在首页),发送路径=收件箱浏览多选+分享扩展。
- 顶栏:左**返回+前进双箭头**(SF chevron 粗圆头 3.2 描边,返回蓝/前进浅灰禁用;前进=返回后可再进入,浏览器式导航历史)、**标题绝对居中**(整页 50% 定位)、右上**「···」圆钮**
- 标签根页无箭头(仅三点);推入页显示返回
- 顶栏下方**搜索框**(灰底圆角+放大镜;按名称过滤当前列表;**只作用当前层——进下级/返回/前进即清空**,原地刷新保留)(2026-11-02 R5a 真机轮 #6)
- 行:通栏、细分割线从行首起;**文件夹=左侧蓝色 › + 蓝色文件夹图标;文件=无箭头 + 问号文档图标**(统一,不按类型区分,用户裁定);副文「日期 - N 项」(文件为「日期 - 大小」);**整行可点**(透明区命中,R3 真机轮 #1/#5)
- **文件夹行 = 箭头行内展开(缩进逐级)+ 行点击进入整页(历史导航)**(2026-11-02 R3 真机轮 #8):点 › = 行内展开子项(› 旋转 ∨,每级缩进 ~18pt,子项同交互:点行进整页、点箭头再展开、可选可全选);一次展开一次拉取(缓存,收起释放);**搜索时收起展开**;返回/前进仍 = 整页历史导航
- **常用目录根行同展开语义**(2026-11-02 R4 真机轮 #1;同日用户裁定回炉):首页收件箱行箭头 = 行内展开子级(同浏览行机制),行点按 = 进整页;**子行点目录直入该目录整页(单目的:子页以子目录为浏览根,返回/边缘右滑直达首页,展开现场原样保留,无中间收件箱页)**
- **下拉刷新**(2026-11-02 R4 真机轮 #4;R5a 修#4):常用目录/设备列表/浏览页三面列表均 `.refreshable`——浏览原地重载(不动历史、展开态保持、子缓存刷新);**与「···」刷新完全同语义(必跑完)——经非结构化 Task 承载解绑 SwiftUI 取消,VM 侧取消=良性收口(保留内容,不伪装「连接中断」)**
- **行左滑**(2026-11-02 R5b 真机轮 #7;2026-11-03 R6 真机轮容器迁 List):文件行才有滑面——本地文件=[发送, 删除];远端文件=[下载, 转发](下载直达本机收件箱;发送/转发进选设备弹层,删除走确认弹窗);**目录行不可滑**(交互走行内展开/选择/进整页);单条目动作与选择模式同流(同一弹层/确认收口)。**实现=R6 起 List + 原生 `.swipeActions`**(R5b 自绘 SwipeableRow 的拖拽与滚动 pan 争用真机恒败;浏览页/首页根列表迁 List,传输列表无争用面维持自绘;删除钮恒贴滑出簇最右,UITest 帧断言钉)
- **「N 项」沉底**(列表尾/底随滚动)
- 「···」菜单:选择 / 排序(名称、日期、大小、种类);设备列表根页为「刷新」

### 4.2 选择模式(「···」→选择 / 行长按 进入)
- 顶栏:**全选(左)/ 居中「N 项」/ 右蓝色圆形白勾确认钮**
- **蓝圈白勾确认=退出选择模式(无论选否,无副作用)**(2026-11-02 Ruling O 真机轮:旧「点确认携带选择集进弹层」废止)
- **首页常用目录同选择面**(2026-11-02 R5b 真机轮 #1):「···」菜单「选择」或长按任意**子行**(depth≥1)进入;**收件箱根行不可选(无圈)**——根行非条目,选择面只覆盖子行(全选/收集天然不及根);选择态**标签栏隐藏在首页同样生效**;底栏/确认/发送(选设备弹层→SendService.send,收件箱内绝对路径=授权根)与浏览页同一骨架同一 VM 面
- **选圈钉行首固定缘**(2026-11-02 R4 真机轮 #3):圈固定在行首 20pt 内缩处,不随树缩进漂移(全行统一列宽,展开子级间无跳面);进/出选择 = 圈滑入/出 + 行内容右移让位;选中蓝底白勾,行浅灰底;搜索框保留
- 底部:**标签栏隐藏**(2026-11-03 R6:可见性声明**条件挂载**——同一导航栈多页同声明时根页声明压过推入页声明,iOS 26 单声明者胜;恒挂三元的根页 `.visible` 曾把推入页选择的 `.hidden` 压住,推入页进选择标签栏不藏);左下功能图标组 + 右下圆点更多
  - 本地(常用目录/收件箱):分享(SF square.and.arrow.up)/ 删除(SF trash,红)
  - 远端(设备页):下载(square.and.arrow.down)/ 转发(square.and.arrow.up)/ **删除(SF trash,红)**(R5b 真机轮 #8:远端选择补删除——deleteSelected 按 vm.deviceId 收口 = ctrl delete {device=对端,paths,force:true},与本机删除同一 VM 面)
- **操作仅自底栏发起**:分享/转发 → 选设备弹层(4.3);下载/删除 → 直发;发起即退出选择模式 + toast「已开始 N 项 · 进度见传输列表」(R3 真机轮)
- **删除一律确认**(2026-11-02 R5b 真机轮 #9):删除走**居中 alert**「删除 N 项?」/「所选项目将被永久删除,不可恢复。」破坏性红钮——选择删除/行滑删/信任目录移除同一确认面(退出登录 R5a #10 先案),无确认不删

### 4.3 选设备弹层(发送/转发确认后)
0.65 屏高 sheet(R3 真机轮 #4:半屏太矮,标题贴抓手——改 fraction 0.65 + 顶距让开):抓手+「发送 N 项到…」+取消(左);设备行同设备页语言(**不显 ›**,R4 真机轮 #2:箭头只属目录行);**在线可选、离线置灰不可选**;点设备即开始传输;下滑/遮罩关闭。

### 4.4 设备页
列表根:行=设备图标(显示器/手机/终端)+名称+「平台 · 在线/最近时间」+右侧状态点(绿/灰);**设备行不显 ›**(R4 真机轮 #2:箭头只属设备内目录浏览行)。点进=远端浏览(4.1 模板,**标题=设备名 | 目录名**(分隔留白,R5a 真机轮 #5),根级单设备名;长标题中间截断——R4 真机轮 #5)。**本机在列**(2026-11-02 R5b 真机轮 #3):列表不滤本机(服务器目录恒含本机)——本机行副文「平台 · 本机」且不可进(浏览自己 = 首页收件箱冗余);选设备弹层仍滤本机(不给发自己)。

### 4.5 传输列表页
分段控件 全部/接收/发送/调度;行=类型徽章(接收蓝/发送绿/调度紫灰)+任务名+**方向设备**(如「公司台式机 → 本机」)+状态:进行中=细进度条+速度+百分比,中断=红字原因,完成=绿勾+时间;最新在最上;**左滑**:↻ 重新发起(中断/失败)/ 🗑 清除(终态);「···」=清除已完成;「N 项」沉底。

### 4.6 我的 / 登录 / 设置
- **我的**:左上扫码图标(占位"敬请期待")、右上齿轮;账号行(字母头像+邮箱+设备名·在线;未登录=一枚「登录」按钮);联系我们/为我打分/我的权益三个占位行(›);退出登录(红字行,**居中 alert 确认**,破坏性红钮——R5a 真机轮 #10);版本号沉底

- **设置页**(推入):我的设备名(默认主机名,点入改)/ 显示隐藏项(iOS 开关,默认关;**本地+远端浏览统一生效**,R5a 修#12)/ **信任目录**(已授权列表+移除;「添加…」开系统目录选择器即授权;小节注明"收件箱默认可见,无需添加")

### 4.7 分享扩展(方案 A,2026-10-31 定稿)
从相册/文件 App「分享 → MTDSS」弹半屏确认页:App 图标+「发送到 MTDSS」+项目清单+**缓存设备列表**(主 App 定期写入 App Group;离线置灰)。**点设备 = 文件+目标一起排队 + 自动拉起主 App 接发**(打开时任务已在传)。扩展不跑引擎。
> 系统约束:iOS 分享扩展拉起宿主 App 有官方限制,存在通行绕法(responder chain)但带审核风险——实现时先验证 `NSExtensionContext.open` 在 iOS 26 的实际行为,绕法作备选并评估;若均不可行,降级为「已排队,打开 App 即自动发送」。
>
> **R6 落地(2026-11-03)**:open() 真机实证不拉起不回调(20261102.4)→ 两级拉起落地:① `ctx.open` 3s 竞窗(部分系统形态 completionHandler 永不回调,Kit firstOrTimeout 兜);② **responder-chain 绕法作守护降级**(仅 open 明确失败/超时后走,自 principal VC 沿链命中响应 `openURL:` 的 UIApplication;审核风险注随码)——双败才落「已排队」注记。**点选即忙状态机**(Kit SharePickFlow):行内 spinner+整表禁点贯穿竞窗,launched=绿勾「已发送」短暂停留后收口,queued=注记即刻呈现;均可换设备重选。sim 实测:外部源(custom scheme)打开宿主会被系统确认弹窗(「在 MTDSS 中打开?」)拦一道——扩展发起的 open 是否同样被拦留真机轮观察(os_log 全程:扩展 top.mtdss.ios.share / 主 App 消费 top.mtdss.ios·share-consume)。

**队列工程与失败语义(builder 评审 #4 补)**:扩展拷贝入 App Group 按 P4a 同款两步(临时名+完成 rename),队列项记录入队时 size,主 App 消费时校验;**拷一半被杀/校验不过的队列项不静默丢弃**——主 App 下次启动在传输列表生成失败态条目(「分享转交失败」),用户可重试(记录人裁定,数据丢失形状的意外不可接受);设备缓存仅主 App 前台期间写入,扩展读到陈旧缓存按离线置灰兜底。

### 4.8 照片图库(R7 Ruling P,2026-11-03 用户裁定:照片库 = 其他设备只读来源;App 内零照片 UI)
照片图库 = **收件箱并列的特殊来源**(非信任目录、非文件系统目录——engine-roots.conf 不含照片库),方向 = **其他设备可读**:授权对端的根列表多出「照片图库」目录,可列相册、可下载照片;对照片根的上传/删除/移动/复制一律拒(**只读来源**)。**App 内零照片 UI**(R5c 的相册/网格/选择/应用内发送随 R7 撤除——首页第二固定行不复存在;数据/导出能力保留转服务化)。数据面 = Photos 框架,Kit 协议化(`PhotoLibraryService` + `PhotoResponder` 应答器在 MTDSSKit;`PHPhotoLibrary` 绑定只在 App 目标——Ruling E)。
- **桥协议**(fdpass 通道复用,daemon→App 事件 + App→daemon 回帧):`fs.photo_list {request_id, path}` → **0x06** `{entries, ok, request_id, truncated}`(path = 虚拟子路径,"" = 根 = 相册列表/目录项[children = 照片数],相册名 = 照片列表/文件项[name/size/mtime_ms/photo_id]);`fs.photo_export {request_id, photo_id}` → **0x07** `{ok, path, request_id}`(App 导出**原始字节** PHAssetResource 到 `{home}/.mtdss/photo-serve/<request_id>/` 回绝对路径;引擎读发后 unlink,App 挂载清扫兜底)。photo_id = 资产 localIdentifier;引擎 stat 走列表缓存,miss 重列父目录。
- **引擎虚拟根**(`DaemonOpts::photo_serve`,仅 iOS 桥 true;桌面/Android 关——零行为变化):守卫对端列根与授权根并列合成「照片图库」条目(children = 相册数);`/照片图库/...` 前缀路由 0x06/0x07,词法规范化后越出根即回落 fs 面(无 `..` 逃逸);下载编排源 = 照片项逐件 0x07 导出临时件后按普通文件传输(真路径+照片可混单)。
- **权限**(Info.plist NSPhotoLibraryUsageDescription,**入口 = 设置页「照片图库」段**):未询问 = 行内「请求授权」(PHPhotoLibrary.requestAuthorization;App 启动不弹);denied = 「前往设置」深链指引;authorized/limited = 已授权/部分照片(子集内照常)。变化流活体跟随。**权限即桥开关**:非授权态应答器一律 ok:false → 引擎按桥不可用收口 → 对端虚拟根隐藏(每次访问现查现答,无通知面)。

## 5. 工程架构

### 5.1 引擎进进程(与安卓路线的唯一变形点)
iOS 禁止 App 创建子进程 → 安卓「mtdssd 子进程+UDS」不可平移。形态:
- mtdssd 编为**静态库**(aarch64-apple-ios)链进主 App,App 启动即在**进程内线程**跑引擎主循环,监听同进程 Unix domain socket
- lib 契约(builder 评审 #3 修):C 面三件套 `mtdss_ios_start` / `mtdss_ios_stop` / `mtdss_ios_ipc_path`;bin 的 prelude(rustls provider 安装、init_tracing、settings/recv_dir 解析)迁入 lib 入口属 lib 化授权范围(非"零改动"红线,桌面 bin 行为不变)
- Swift 侧监督:hello 心跳失败→进程内重启引擎线程,连续失败升级错误横幅(授权 builder 定细节)——iOS 无进程隔离,安卓"子进程死=可检测重启"的语义由此面承接
- Swift 是 `crates/ipc` 契约的**又一客户端**(与 Kotlin 同款打法):ipc JSON over UDS;**golden JSON 双端防漂移**直接复用(安卓 51 文件锁定 → iOS 对齐)

### 5.2 文件系统
- 沙箱直通:文件三原语(open_source/create_dest/ls_source)在 iOS 走 std::fs 桌面退化路径(无 SAF 层)
- 收件箱=App Documents(UIFileSharingEnabled+LSSupportsOpeningDocumentsInPlace → 文件 App「我的 iPhone/MTDSS」可见)
- 信任目录=UIDocumentPickerViewController 选目录 → **安全域书签**(security-scoped bookmark)持久化,引擎经书签解析访问
- 收件暂存=App 私有 `.mtdss` 隐藏目录(对文件 App 不可见),完成发布两步 move+rename(P4a 语义;r2 教训:rename 不跨目录须同目录两步)

### 5.3 进程与生命周期
- 前台=在线:App 挂起即引擎断线,任务标中断(不额外做 beginBackgroundTask 续命——安卓同款语义,预期内)
- 任务持久化在引擎侧(tasks.json 原子写),App 重启恢复列表(P2)

### 5.4 Share Extension
- 独立 target `top.mtdss.ios.share`,**不链引擎**(扩展内存限额+秒级寿命,系统硬限制)
- App Group `group.top.mtdss.shared`:①转交队列(扩展把分享文件拷入共享容器+写 job 意图含目标设备)②设备列表缓存(主 App 定期写入)
- 主 App 启动/回前台时消化队列:文件转正式发送(引擎接管),清队列
- 拉起宿主:见 4.7 风险注

### 5.5 身份与签名
- bundle ID `top.mtdss.ios`(个人账号;公开上架若介意卖家名显示个人姓名,后续转公司账号可迁移)
- 开发+发布证书/描述文件经 App Store Connect;TestFlight 外部组(个人号无内部团队席位;每版本首构建过轻量 Beta 审核)
- 传输中 FLAG_KEEP_SCREEN_ON 对应 iOS `isIdleTimerDisabled`

### 5.6 权限
- **本地网络权限(必备,2026-10-31 builder 评审补)**:引擎直连优先 RFC1918 私网候选(同 Wi-Fi PC↔iPhone 是旗舰场景),iOS 14+ 对本地网络单播连接强制 `NSLocalNetworkUsageDescription`,缺失时**系统不弹窗、静默断连**。Info.plist 必带,文案(记录人拟,用户可否):「MTDSS 需要在本地网络中查找并连接你的其他设备,以实现高速直连传输。」
- 通知权限(本地通知)弹一次;沙箱+书签授权模型无其他特殊权限(毙 MANAGE_EXTERNAL_STORAGE 的 iOS 同理)。
