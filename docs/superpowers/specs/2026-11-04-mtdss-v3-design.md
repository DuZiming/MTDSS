# MTDSS V3 总体设计(伞形) 设计稿

日期:2026-11-04 | 状态:**已批准**(2026-11-04 用户终审同意;含 builder 评审六问闭环与 §11 十条裁量)
来源:2026-11-03/04 brainstorm(承接 2026-11-03 V2 平台回顾与对齐分析),决策人为用户本人,记录人为 Claude。
体例:本文件是 V3 **伞形总体设计**,钉死跨波次的语义与边界;每波(V3-1…V3-5)开工前另出独立 spec + 实施计划(沿 V2 惯例),冲突时以本文件为准。

## 1. 意图与背景

V2 已收官(Windows 1.1.0 已打包、安卓 v1+iOS v1 已合并),MTDSS 从「自己的工具」升级为**邀请制小规模产品**:给朋友、同事使用;对外发布演示视频吸引感兴趣的人;由运营者(用户本人)开账号放行,**有名额与终端数口子,不是开放注册**。

**为什么现在**:三端客户端与引擎已实盘稳定,剩余差距集中在「跨端语义对齐、账号安全、产品化门面、体验打磨」——正是把外部人放进来的前置条件。

**信任边界的根本变化**:账号成为唯一的大门(设备间=同账号全家),因此账号安全体系(V3-1)是全部工作的地基;视频即门面,UI 颜值与可读性优先级高于功能数量。

## 2. 目标 / 非目标 / 反目标

**目标(V3)**:
- 账号安全体系:受信终端模型 + 扫码登录 + 新终端授权 + 终端数上限(§3)
- 常用目录系统:账号级同步、混合视图、终端标志色(§5)
- 三端语义对齐:以 iOS v1 承载的语义为跨端基准(§7)
- 产品化门面:UI 改名 Synshu/星枢、图标统一(§6)
- 已知 bug 与体验打磨清偿(§8)

**非目标(V3 明确不做)**:
- 官网/落地页/网页管理后台(仅 admin CLI;以后版本)
- 开放自助注册(仍邀请制,admin 开号)
- 探索项(§10)不进验收线:手机后台常驻、隧道预就绪、免下载预览/缩略图——只调研/顺手关注,收官复盘定 V4
- 手机端「往常用目录里放文件」的场景(手机端常用目录动作=下载/发送类,无放入入口)
- daemon/cli 改名(mtdss 恒为技术底座名)

**反目标**:
- 审批可绕过:凡「有受信终端在线」的场景,不给任何自动降级缝
- 三端像素级一致:安卓视觉保持 Material 3 原生,只对齐架构/操作/交互
- 引擎重写:一切在既有 Rust 引擎 + golden 契约单一真源之上做
- 桌面零回归原则破坏:既有桌面行为除明示改动项外逐字节不变

## 3. 账号安全体系(V3-1 核心;2026-11-03/04 用户裁定)

参照 Apple 账号骨架(设备弹码为主、永远可用的带外通道兜底),映射:我们的「带外通道」=邮箱验证码(登录本体,永远可用,不依赖任何终端在线)。

**受信终端模型**:
- 账号的设备清单内的终端=受信终端,各持持久设备凭据;**凭据在清单的老终端重连/换网络零审批直进**——审批只针对清单外的**新**终端;
- 新终端接入三路径:
  1. **扫码**(推荐主路径;仅「新终端=PC」方向,用户 2026-11-03 原始钦定范围):PC 显示二维码→任一**已登录**手机/终端扫码+点「同意」→直接进。**知情即授权,不叠加输码**;新手机终端不设扫码(手机互扫不做),走路径 2/3;
  2. **邮箱登录 + 有受信终端在线**:邮箱码照走 + 在线受信终端**全部**弹审批+验证码 → 新终端输对码 → 进;拒绝或无人应答 → **不进**。**不自动降级**(在线但主人不在=改天再登或掏手机扫码;记录人裁定,防绕缝);
  3. **邮箱登录 + 无受信终端在线**(账号第一台,或老终端全下线):邮箱码单码直接进,**自动成为受信终端**(信任锚可迁移到「起得最早的那台」)。
- 窗口期风险接受:握有邮箱码者可在「无终端在线」窗口进入并操作(含踢设备),与 Apple 接受的短信兜底风险同级(用户知情确认)。
- **「在线」的定义与推送边界**(2026-11-04 记录人裁量):在线=当前与信令服务器保持连接(WS);**V3 不引入 FCM/APNs 推送**(与安卓「无常驻无通知」既有裁定、§10 探索定位一致)——移动端未开 App 即不在线、不弹审批,桌面常驻端是弹码主力。presence 判定阈值是路径 2/3 的**安全边界**(过松→该审批的走了单码直进;过严→把登录者锁死在无人应答),取值归 V3-1 spec。
- **多端在线裁决**(2026-11-04 记录人裁量):全端弹**同一**审批卡(同一验证码+同意/拒绝钮);**先到先裁**——任一台点「同意」或新终端输对码=通过,全端撤卡;任一台点「拒绝」=一票否决,本次尝试终止;超时(5 分钟量级,定值归 V3-1 spec)无应答=尝试过期不进。
- **设备跨账号换绑**(2026-11-04 记录人裁量):换绑=对目标账号的「新终端接入」,完整走目标账号审批;成功后原账号自动解绑并吊销旧凭据(堵住现有服务端 auth 换绑可绕审批的路径,V3-1 改造)。
- **邮箱码真实投递**(2026-11-04 用户裁定:阿里云):现状=验证码直接随 HTTP 响应返回(自用期开发模式,服务端无邮件发送代码);V3-1 接入**阿里云邮件推送**(发件域 `mtdss.top`,SPF/DKIM),验证码改真实邮件送达、不再随响应返回;服务商凭据经服务端环境注入,不落库。
- 最后兜底=运营者 admin 命令(解绑/重置),不做 iforgot 类自助恢复。

**终端数上限**(4a/4c 用户裁定,2026-11-04 修订):
- 上限由服务端按账号配置(admin 命令);设备清单长度(含离线)恒 ≤ 上限;
- **不自动踢**:新终端完整通过认证**之后**,进入强制选择屏——从设备清单挑一台踢出(凭据吊销、清单移除、对端被通知下线),踢成功才留在登录态;**不选/取消 = 该新终端自己退出登录**;
- 踢出选择屏对三路径(扫码/邮箱±弹码)统一适用。

**admin 命令面**(服务端 CLI;V3 仅此,不做网页后台;记录人裁量补两条):
- `设置用户终端数上限`(用户钦定最小集)
- `查用户设备清单`(裁量补:运营兜底)
- `解绑某台设备`(裁量补:账号恢复最后手段)

**服务端新增「账号数据」存储**(V3-1 打地基,V3-3 消费):账号作用域的元数据 KV,首个用户=常用目录清单(§5);同步机制(登录拉全量 + 变更推送/拉取)在 V3-1 spec 细化。

**任务命名规则**(用户裁定「规则可以」,引擎侧小改,随 V3-1 捎带):
- 任务名=内容代表名,**发起方创建任务时生成并写入任务记录,两端从记录同读**(不各自拼装——统一之根);
- 代表名取法:单文件=文件本名;单目录=顶层目录名;多项=「首项名 等 N 项」;
- 方向与对端设备名不入任务名(由列表方向列/副文承担);
- PC 接收列表现「乱名/一串 ID」的显示面一并收敛到此规则。

## 4. 收件箱与信任目录统一模型(2026-11-04 用户裁定)

- **收件箱=各端默认的本地文件存储目录,天然始终信任,置顶于常用区**;它只是一个本地目录,**与传输实现机制解耦**;
- 目录名统一 `MTDSS`(不用中文名/不用品牌名);默认落点:Windows=`文档\MTDSS`(可用既有 set_recv_dir 改)、Android=`Download/MTDSS`(SAF 授权)、iOS=App Documents/MTDSS(iOS 无系统级下载目录可写,Documents 即平台等价物,**维持现状**);
- **中间态语义全端统一**:传输中间态文件只存在于隐藏记账区,完成后才以本名出现。桌面现行 `.mtdss` 记账+finalize rename 机制由 V3 计划**逐行核验**——若存在「半截文件裸露在收件目录」的路径则对齐补齐,若本就隐藏则仅改默认落点;
- **电脑端默认全盘开放**(现状不变),提供**可选收紧**为「信任目录模式」(引擎 RootGuard/`authorized_roots` 现成,Windows 配置注入即得;不开=直通,桌面零回归);
- 手机端信任目录=收件箱+用户添加(安卓对齐 iOS 书签/授权根模型);
- 「允许删除远端文件」安全门三端统一,**默认全关**(§7)。

## 5. 常用目录系统(V3-3;2026-11-03/04 用户裁定)

- **数据模型**:账号级同步的清单——常用目录 = `{名字, 成员[{设备, 路径}]…}`;**收件箱例外**:它是每台终端自己的本地默认目录,不进账号同步,但同样置顶于常用区;
- **直达**:把 A 终端的「下载目录」存为常用目录后,任何终端打开常用区点它即达,无需逐层浏览;
- **混合视图 = 各成员目录快捷方式的合并**:内容合并展示,操作能力与在各设备目录里**完全对等**(浏览/下载/转发/删除/复制…),操作路由到文件真正所在的设备;
  - PC 多选拖拽复制到本地=跨多设备文件汇聚到本地;
  - PC 从本地拖文件进**多成员**常用目录 → 弹层选「存到哪个成员目录」;单成员直进;
  - 手机端动作=下载/发送类,无「放入」场景;
- **终端标志性颜色**:每台终端自动匹配一种固定标志色,**避开常用状态色与警告色**(蓝=进行中/绿=完成/红=失败类语义色保留);混合视图内文件行按来源终端着色,同色=同源,同名文件一眼区分;单终端多目录同名文件同色(不管);颜色的分配与稳定策略(device_id 派生/服务端分配、跨端一致)在 V3-3 spec 细化;
- 各端落位:Windows=侧栏「常用目录」区(P4b 的 V2 占位兑现)+ 主区混合视图;iOS=「常用」标签扩展;安卓=随 V3-4 新架构落。

## 6. 品牌切换(V3-2;用户钦定)

- UI 程序改名:英文名 **Synshu**、中文名**星枢**;
- **只改 UI 层**:安装器/窗口标题/App 显示名/托盘(含托盘图标)随品牌;底层 daemon 与 CLI 恒为 mtdss——定位表述:「mtdss 是技术底座,Synshu(星枢)是基于 mtdss 底座的客户端产品」;
- 多终端程序图标设计统一(同一品牌标记跨 Windows/Android/iOS);图标/视觉稿需用户过目后落地。
- **分发与签名**(2026-11-04 用户裁定):Windows 安装器**暂不购代码签名证书**——接受 SmartScreen 首装警告,演示视频/下载页提供「更多信息→仍要运行」引导话术;Android 继续 **APK 直装**(/dl 分发路径);签名证书与 Google Play 轨道待规模验证后再上。

## 7. 三端语义对齐(V3-4;基准=以 iOS v1 承载的最新裁定语义)

V2 回顾结论:引擎契约层已三端锁定(golden 单一真源),分叉集中在平台接线层与 UI 层,对齐成本低。对齐清单:

| # | 项 | 基准语义 | 各端差距 → V3 动作 |
|---|---|---|---|
| 1 | 被浏览授权根守卫 | iOS:引擎 RootGuard+授权集+合成根列表 | 安卓:SAF 根纯 Kotlin 侧、被浏览=沙箱直通无守卫 → 安卓把 SAF 根映射注入 `authorized_roots`,对端见合成根列表;Windows:默认全开不变+可选收紧(§4) |
| 2 | 允许删除远端文件 | iOS:设置页安全门,默认关 | Windows:补同等安全门(现有回收站确认梯保留);安卓:随新 UI 补删除入口+门 |
| 3 | 相册/照片图库虚拟根 | iOS:`/照片图库` 只读虚拟根,权限即数据面 | 安卓:Kotlin 侧照片应答器接线(引擎 photo.rs 平台无关现成);Windows/其他手机端对安卓相册的浏览随之打通 |
| 4 | 手机端分享扩展 | iOS:App Group 队列+暂存转交,可重试 | 安卓:现 ShareActivity 一次性 content URI,中断=「源已不存在」→ 对齐为暂存转交可重试模型 |
| 5 | 显示隐藏项 | iOS:设置开关,默认关 | Windows/安卓:对齐补开关 |
| 6 | 设备名设置 | iOS:设置页改名(下次登录生效) | Windows:从登录高级选项迁到设置面;安卓:从登录表单迁到设置面 |
| 7 | 手机端 UI 架构 | iOS:四标签(常用/设备/传输/我的)+浏览模板+选择模式+任务分段(含调度) | 安卓:**架构/操作/交互三对齐,视觉走 Material 3 原生**(不做 iOS 高仿);**先出 UI 设计稿过用户审,通过后再实施**;安卓任务列表补「调度」类显示 |
| 8 | 收件箱置顶常用区 | §4/§5 | 三端统一落位 |

## 8. 已知 bug 与体验打磨(V3-5 为主;用户清单)

- **iOS 分享文件保原名**:分享转交的文件必须使用原文件名,不得改名/破坏扩展名(iOS 现出现);
- **任务名统一**:§3 任务命名规则落地,PC 接收乱名/ID 串清偿;
- **Windows 查看-列表**:表头**固定**(滚动不消失);表头**非悬停不高亮**;
- **Windows 查看-平铺**:图标太小、展示效果差 → 改版(尺寸/信息密度重做;与 §10 缩略图探索呼应但**不依赖**它);
- **Windows 任务数据持久化 + 排序**:任务记录跨重启持久;**最新任务在上**(Windows 与安卓现状都有问题,安卓侧随 V3-4 新 UI 修);
- **Windows 主题收敛**:三主题(fluent/workbench/dark)退役,**收敛为白/黑两套,默认白**(推翻 P4b 默认 dark 的裁定,用户 2026-11-04 钦定);黑白各精修一套 token;
- PC 收件箱默认落点改 `文档\MTDSS`(§4)。

## 10. 探索项(V3 不做验收线;2026-11-04 用户裁定)

做的时候顺手关注;收官复盘定下一版方向:
- **手机后台常驻**(像微信):与 V2 安卓「无常驻无前台服务无通知」的商店合规裁定相反;iOS 基本只有短时续命窄门 → 倾向仅出调研结论;
- **隧道预就绪**:免每次点设备才打通;调研连接预热/保活方案;
- **目录加载慢**(有时快有时慢甚至失败):按 **bug 调查**排进 V3-5 前,大概率可修;
- **免下载预览/缩略图**(平铺缩略图、图片预览):调研方案后做不做看成本。

## 11. 记录人裁量清单(用户未见逐条批准,交审时一并过目)
