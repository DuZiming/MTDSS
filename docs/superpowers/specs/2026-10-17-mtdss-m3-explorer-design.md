## 1. 意图与为什么

M1/M2 交付了「能传」:账号/设备登记、NAT 打洞、分块断点传输、混沌下的可靠性。M3 交付「好用」:MTDSS 从「发送文件的工具」变成**跨设备文件资源管理器**——像操作本机资源管理器一样,浏览、复制、移动、删除自己所有登录设备上的文件。

Brainstorm 定调的核心判断:

1. **心智模型 = Windows 资源管理器/访达**,学习成本趋近于零;
2. **同账号 = 同一个人的设备**:默认全开放、远端无人值守、没有任何对端确认;信任边界就是账号本身;
3. **平台策略**:daemon 三平台常驻,**daemon 是设备上唯一连接服务器与其他设备的模块**;CLI 是配套命令行工具(纯 IPC 客户端);**图形 UI 仅 Windows**(M3)。

## 2. 用户模型与信任

| 事实 | 设计后果 |
|---|---|
| 设备登录同一账号 | 授权 = 信令服务器的同账号设备列表 + QUIC 证书互验(M1 已有),V1 不新增任何授权流 |
| 远端无人值守 | 远端操作(删除/写入)不弹任何对端确认 |
| 默认全盘开放 | V1 可浏览/操作远端全部盘符 |
| 部分用户会有顾虑(V2) | 设置加「按设备开放范围」「允许远端删除/剪切」,默认全开 |

安全边界沿用 v1 spec §4/§5:QUIC + TLS 1.3、证书互验(对端公钥 = 服务器登记值)、punch 包 HMAC。账号被攻破 = 全设备文件可及——这是产品模型接受的既有风险,V2 的开放范围设置是缓解项。

## 3. 主窗口(唯一窗口)

```
┌─ MTDSS — 我的台式机 — D:\项目 ────────────────────────┐
│ 新建(占位) | 剪切 复制 粘贴 删除 | 排序▾ 查看▾          │  工具栏
│ ← → ↑  🖥我的台式机 ▸ 数据(D:) ▸ 项目      🔍搜索当前目录 │  地址栏
│ ┌──────────┬───────────────────────────────────┐ │
│ │▸常用目录  │  列表:名称 ↕ / 修改日期 / 类型 / 大小      │ │
│ │ (V2 占位) │                                    │ │
│ │▾MTDSS设备 │  (内容区:平铺 / 列表 / 详细信息)         │ │
│ │ ▾本机 ●   │                                    │ │
│ │ ▾台式机 ● │                                    │ │
│ │ 笔记本 ○灰│                                    │ │
│ └──────────┴───────────────────────────────────┘ │
│ 5 个项目,已选 1 · 信令:在线 · ↓ 32 MB/s(1 个传输中)   │  状态栏
└──────────────────────────────────────────────────────┘
```

- **工具栏**:新建(**占位**,内容 V2 再定)/ 剪切 / 复制 / 粘贴 / 删除 / 排序(仅名称,递增|递减)/ 查看(平铺|列表|详细信息,**默认详细信息**)。按钮就是按钮,不显示选中状态。
- **地址栏**:←/→/↑ + 面包屑(设备 ▸ 盘 ▸ 目录)+ 搜索(**仅过滤当前目录**);顶层 = 设备列表视图(侧栏点「MTDSS设备」节点同效)。
- **左侧树**:「常用目录」(占位;V2 支持把任意设备的常用目录手动加进来)与「MTDSS设备」均可整点点击或逐级展开。「MTDSS设备」下 = **全部设备,含本机**——本机置顶并标注「本机」,与其余设备完全同构(盘符 → 目录逐级展开);**设备命名默认取主机名,可自定义**(首启命名;设备列表右键「重命名」)。
- **内容区**:三种视图;多选 = Ctrl 点 / Shift 点 / 框选;双击文件夹 = 进入;**双击文件 V1 无操作**(V2 预览/打开)。
- **状态栏**:当前目录项数、选中数、信令在线状态、传输速率汇总。

**树节点态**:在线设备正常;**离线设备灰、不可点、不可展开**;正在浏览的设备掉线 → 停留当前页(后续操作报错),离开后不可再进入。

## 4. 交互矩阵

### 4.1 右键菜单与快捷键(V1 主交互)

右键菜单:打开(=进入,仅文件夹)/ 剪切 Ctrl+X / 复制 Ctrl+C / 删除 Del;粘贴 Ctrl+V。

| 方向 | V1 | 机制 |
|---|---|---|
| 本机 → 远端目录 | ✅ | 读系统剪贴板/拖入的本地路径,走既有上传(manifest + 分块) |
| 远端 → 本机(拖出到系统) | ✅ 桌面;资源管理器窗口待验证 | 拖出时向系统**仅示意可放、不交付数据**;松手取鼠标落点解析目标路径:**桌面 = 系统已知文件夹,稳(V1 支持)**;**资源管理器普通窗口 = 向窗口查询其当前文件夹**(M3c 做一次验证性尝试,不稳则 V2)。解析成功 → 自有引擎接管(文件+目录、隐藏暂存、续传、自有进度窗);解析不出 → 提示「请拖到桌面/下载到本机」 |
| 远端 → 本机(窗口内) | ✅ | 拖/粘贴到树中**本机设备**的目录 = 同引擎本地落盘,路径天然可知 |
| 远端 → 本机(稳妥路) | ✅ | 右键/菜单「**下载到本机…**」:系统目录选择器 → 直落盘,断点续传 + 自有进度窗 |
| 远端 A → 远端 B | ✅ | 操作端 X 编排:A 发送、B 接收(复用既有传输引擎与打洞),数据不经 X 落地 |
| 同一远端设备内 复制/剪切 | ✅ | 远端 FS 操作(§5.2),无网络传输 |
| MTDSS → 真实资源管理器的 Ctrl+V 粘贴 | ❌ V1 不做 | 粘贴没有「松手坐标」可借,落点不可知(拖拽有) |

**剪切语义**:跨端剪切 = 传输完整成功后删源(尽力进源端回收站)。
**粘贴写入远端**:直接写显式目标路径,不需要任何远端确认。

### 4.2 拖拽

- **拖拽语义跟 Windows 资源管理器惯例**:跨设备拖 = 复制;同设备内拖 = 移动;剪切+粘贴 = 移动(成功后删源);V1 不做 Shift/Ctrl 修饰键改义。
- 本机资源管理器 → MTDSS 窗口(远端目录)= 上传(简单方向,Tauri 内建 drop);
- MTDSS 窗口 → 桌面 / 资源管理器窗口 = 落点解析 + 自有引擎(§4.1);
- MTDSS 窗口内:远端 A 目录 → 远端 B 目录 = A→B 传输;同设备目录间 = 远端 move;任何设备 → 本机设备目录 = 本地落盘任务。

### 4.3 冲突、删除与暂存

- **同名冲突**:Windows 式对话框——单文件「跳过 / 覆盖」,批量加「全部跳过 / 全部覆盖」;
- **删除**:默认静默进**远端**回收站(`IFileOperation` + `FOFX_ALLOWUNDO`,Windows;Linux/macOS 无回收则操作侧确认后永久);V2 加「允许远端删除/剪切」开关;
- **隐藏暂存夹(传输中间态,本设计新定)**:所有传输(含本地复制)的中间态收进**目标目录下的隐藏暂存夹**(沿 M2 既有的 `.mtdss` durable 记录机制,收编散落的 `.mtdss-part` 为一个隐藏目录),完成后改名落位、清理暂存;目标目录全程不被中间态污染。原「`.mtdss` 保留段大小写敏感」债务并入本项一起做。

## 5. daemon 与协议扩展

### 5.1 `crates/daemon`(新,三平台)

常驻进程:core + 信令客户端 + 账号/设备凭据 + 远端 FS 服务端 + IPC 服务端;Windows 版另含托盘。

- **三平台**:Windows(托盘)/ Linux、macOS(headless,无托盘无 UI);同一代码;
- **托盘**(`tray-icon`,仅 Windows):登录 = 亮色图标,登出 = 灰色;右键菜单 = 登录/登出、设置(先只有开机自启)、打开主窗口、退出;开机自启 = 注册表 Run 键(设置开关);
- **IPC**:Windows 命名管道 / Unix domain socket,JSON-RPC 2.0(请求/响应)+ 事件推送(设备在线变化、目录内容、传输进度、通知),OS 权限限本用户;
- **daemon = 唯一的常驻连接者**:本机只有 daemon 连接信令服务器(WS)与其他设备(QUIC);身份种子、JWT、peer 证书钉扎全部由 daemon 唯一持有;CLI 与 UI 不得直连服务器——不存在同设备多连接,**信令服务器在线模型零改动**;
- **CLI = 纯 IPC 客户端**:register/login/logout、设备列表、远端资源列表、上传/下载等一切操作经 daemon 接口完成;现有 `flow.rs`/`session.rs` 的直连逻辑迁入 daemon(会话目录由 daemon 接管);daemon 未运行时 CLI 自动拉起本机 daemon(后台),拉起后仍未登录则命令返回明确的「未登录」提示并指引登录;
- **UI 与 daemon 完全解耦**:UI 崩溃/关闭不影响传输;重开自动重连 IPC;未登录时主窗口 = 引导态(「从托盘图标登录」)。

### 5.2 控制通道与远端 FS 协议(proto 扩展,做进 core)

- 同账号设备对之间建立**控制通道**(QUIC 之上,常驻或按需,plan 定):`list` / `stat` / `delete` / `move` / 传输编排指令(让 A 给 B 发、让 B 准备收);
- **远端 FS 服务在 core 内实现**:daemon 与独立 CLI 均可承载 → Linux/macOS 的 CLI 机器与 Windows daemon 机器在树里平权、均可被浏览与操作;
- `list` 返回名称/大小/mtime/类型;**隐藏暂存夹与 `.mtdss-part` 一律不列出**(沿 intake 既有规则);
- 新消息带版本头,沿 manifest 既有 proto 版本机制;全部增量式 + 能力协商,保证旧版 CLI↔CLI 通路不被破坏。

### 5.3 `ui/`(新,Tauri v2)

React + TypeScript + Vite;i18n 框架就位,V1 仅中文;登录表单亦在主窗口引导态内,托盘「登录」项在 UI 就绪后改为唤起主窗(M3a 仍置灰)。

## 6. 传输管理

- 每个我方传输 = 一个 Windows 式复制小窗(进度/速度/暂停/取消);
- 状态栏速率汇总 + 托盘进行中计数;
- **通知**(系统通知):写入方与被写方都收到完成/失败;被写方知晓「台式机 向 D:\项目 写入了 3 个文件」;
- 断点续传:会话内(M2 既有);跨会话 V2。

## 7. 账号与首启

沿用 M1 既有:邮箱 + 6 位验证码(dev 模式回显;真实邮件服务 V2/M4 接入)。首启:托盘引导 → 登录 → 给本设备命名(默认主机名)→ daemon 生成 Ed25519 设备密钥并登记;daemon 接管既有 CLI 会话目录(身份种子/服务器地址/CA 平滑迁移)。

## 8. V1 非目标(占位或明确不做)

常用目录(占位)、新建按钮内容(占位)、文件预览/打开、重命名(文件)、跨会话断点续传、限速、移动端、mDNS、按设备开放范围、远端删除许可开关、真实邮件服务、传输历史页、MTDSS→真实资源管理器的剪贴板粘贴、Linux/macOS 图形界面、拖到资源管理器普通窗口(若 M3c 验证不稳,降 V2)。

## 9. 反目标(做了就算失败)

- 任何「对端确认 / 接受文件」弹窗(旧收件箱模型回潮);
- UI 与传输强耦合:UI 崩溃/关闭导致传输中断;
- **让系统资源管理器经手数据**:先下临时目录再搬运、或把占位/空文件交给资源管理器复制——拖出必须「落点解析 + 自有引擎直落」;
- CLI 或 UI 绕过 daemon 直连服务器(一切远端操作必须经 daemon);
- 破坏测试集与 nat-matrix CI 门禁。

## 10. 约束

- 工作区结构沿 v1 spec §9:新增 `crates/daemon`、`ui/`;
- 测试策略:核心逻辑(core/daemon)单测 + 集成;UI 冒烟;Windows 拖出落点解析层隔离成薄模块,可单测 + 手动冒刺;CI 门禁不变(`cargo test --workspace` + `clippy --all-targets -D warnings` 双平台 + nat-matrix);
- **混版本互通 = 非门禁**(尚无外部用户,开发期自有设备同步升级);硬约束 = 测试集与 nat-matrix 保持全绿,但**测试形态迁移**:e2e/nat-matrix 从「独立 CLI 直连」改为「daemon + CLI(经 IPC)」;
- **带入债务**:①`transfer.rs` 收端终局 EOF 舞步无界——随 daemon 生命周期重设计按 2s 有界方案修复(本次做);②`.mtdss` 大小写敏感——并入隐藏暂存夹重做(§4.3);
- 开发环境(本机):rsproxy 镜像、protoc 完整路径、gh 需手动 PATH、git 走 SSH(见项目记忆)。
