## 3. 特性 A:接收轮并发化

**结构**:轮循环退化为**纯取件派发器**——等来件、做完轮前置(绑定/路由判定/inbox_dest 构造),然后把**轮本体 spawn 成独立任务**;全局信号量限并发(默认 **N=3**,调优旋钮族,env 可调,同 ctrl keep-alive 族纪律)。

**每轮任务自有**:broadcast 订阅(`hub.subscribe()` 每轮一订,握手候选用)、relay 事件订阅、round handle/watch、登录与关停 watch 克隆。**轮循环本体只持有 `req_rx`**(每代际单枚,不可克隆)。

**不变项(红线)**:
- XferSlots 按设备单槽语义不动(同设备并发第二笔暖资格失败→落打洞臂,与发送端 `try_xfer_lock` 镜像);
- 暖臂/打洞臂结构与 Stage B 收口段逐行不动;
- 协议面零改。
- inbox 发布协调器(`begin_publish`)并发安全在计划期核;不安全则发布段串行化(发布是本地 IO,非网络瓶颈)。

**mux 队头阻塞票联动收口**(§7-1):并发化后多轮共连场景放大,随本特性一并处理(每流 spawn 化的具面在计划期定)。

## 4. 特性 B:失败记忆中继优先 + 中继并行预备(中继过渡桥 + 探洞回切)

三层叠加压缩「连不上」的连接时间:**并行预备**(§4.2,每轮首笔省串行分配段)→ **armed 记忆**(§4.3,第二笔起免打洞等待)→ **探洞回切**(§4.4,直连恢复即回切)。中继全程只做备用。

### 4.1 状态机(per-peer 记忆表,daemon 全局)

```
per peer: { 穷尽计数, 最后穷尽时间, armed 代际号 }
打洞穷尽(传输轮)        → 计数+1;**计数 ≥1 即 armed**(用户语义:「打洞失败后
                          通过中继连上」——单次穷尽即生效,验收线「第二次起直进中继」)
任一次直连成功(打洞成/暖池命中/暖插入) → 计数清零、armed 撤销
TTL(15min)无新穷尽      → 计数衰减**归零**,armed 随之失效(warmer 冷却窗盲区的
                          安全阀;重 armed 需一次新鲜穷尽)
```

**稳态节奏**(物理不通对,设计预期):每段 ≥15min 静默后的首笔传输付一次打洞穷尽学费(并行预备已把中继备好,穷尽即切无串行段),随后 relay-first 直到再次静默——轮间 warmer 探洞成功可提前解armed(暖池有直连时传输走暖臂,记忆面根本不进)。**armed 的周期性失效就是轮间恢复机制**(§4.4 的 30s 探洞只跑在活跃中继轮期间,与 warmer 常规探洞互补)。

**误伤面与缓解**(阈值 1 的代价):单次瞬态打洞失败也会 armed,但①任一直连成功即清(瞬态失败的下一次探洞大概率即成)②armed 轮中继失败反转兜底仍试打洞③活跃中继轮 30s 探洞快速回切——三层兜底把误伤窗口压到分钟级。

### 4.2 并行预备——打洞与中继分配赛跑(未 armed 传输轮)

**打洞开局 3s(≈首轮互拨失败;调优族)仍未直连 → 并行发起中继分配**(中继资格在手时;资格不在手不预备,行为零改)。打洞继续跑满预算,两条线并行:

- **打洞穷尽** → 中继会话已在手(分配+互拨与打洞并行完成)→ **立即切换**——省去现行「穷尽后才分配再互拨」的 10-20s 串行段,连接时间从 30-50s 压到打洞预算本身(10-30s);
- **打洞成功** → 用直连,**弃中继会话**:显式释放(协议有面则用;无面则关客户端中继连接触发快速回收,计划期定形);
- **分配被拒**(并发上限等)→ 优雅降级:照现行串行兜底语义(穷尽后再试分配/按现行失败面收口),并行预备不放大失败;
- **响应方时序容忍**:提前到达的分配推在订阅缓冲里等响应方自家编排(「先订阅后回信」纪律既有);发起方打洞成功弃中继时,响应方可能已收到推 → 死会话按既有 Dead/idle 面自然忽略。

**配额纪律**:并行预备=短暂占槽(常态 2-30s,打洞成败即定弃取);8 槽/账号下同账号多设备同时传输的瞬时峰值可容忍(§E9 五路并发占 5 槽仍有余量);弃单**显式释放优先**(不赖 60-120s 空闲回收)。

**armed 轮无需预备**:armed 已跳过打洞,中继即主线(§4.3),不占「预备」语义。

### 4.3 armed 轮的连接编排(`connect_with_fallback` 消费记忆)

**记忆范围=仅传输面**:计数与消费都只挂传输轮(send_round `flow.rs` 打洞段 + 接收握手 `recv_handshake` 互拨段);ctrl/浏览面(`dial_session`/`respond_session`)维持现状零改(warmer 自管,「配额面零改」红线保持——浏览不因记忆改走中继)。

- **发起方**:armed ∧ 中继资格在手 → **跳过直连段**,直接 `relay_via_allocate`;资格不在手 → 维持现状(直连穷尽后失败,不上报「中继优先」误语义)。
- **响应方**:armed → 握手臂跳过互拨段,直接等中继推(`relay_via_push`);**等推窗 armed 态 5s→45s**(调优族)——armed 意味「直连已知不通」,对端未同步 armed 时其打洞穷尽需 10-30s 后才分配+推,45s 盖过之,免一轮空败;双侧同步 armed 常态 ~1-2s 即达,窗口无感。未 armed 对端仍互拨——双侧记忆独立,不对称 armed 无死锁(中继 rendezvous 各走各的推送/分配,punch 需双方但失败即弃;失步成本被 45s 窗吸收)。**无资格闸注记**(实现裁定):响应方等推不设资格闸——推到达即证资格在场,闸只在「推永不到」路径起作用且会在资格陈旧窗反向伤人;armed∧中继全局停用的角落退化为 45s 空等+反转补拨,有界且随 HelloOk 资格刷新自愈。
- **中继失败反转兜底**:armed 轮中继编排失败(可重试类 `RelayFailed`)→ 当轮**仍试打洞**(反转兜底,保活命;打洞成功同轮直连,且按上表清 armed)。
- 日志三行:armed 建立 / armed 命中(跳直连)/ 回切。作业卡中继角标(`mark_relay`)照旧。

### 4.4 探洞与回切(治瘾机制)

- **轮间**:warm 预热器既有退避照旧(armed peer 不特殊化)。
- **活跃中继轮期间**:该 peer **豁免 warmer 冷却窗**,探洞节奏 ~30s/发(单发=STUN+互拨,成本秒级;长中继传输里可忽略)。中继传输常为蜂窝大文件,这正是回切收益最大面。
- **探洞成功 → 三步回切**:
  1. 直连入暖池(mux 协商照 Stage B 语义);
  2. armed 撤销、计数清零;
  3. **在途中继作业主动轮换——探洞方关闭自己的中继半连**(统一形状,两种拓扑都成立):
     - 探洞方=发送端:关己侧中继连 → 自身重试轮落暖臂=直连,位图续传零重发;
     - 探洞方=接收端(warm 目标单侧主动=小公钥侧,常恰为接收端):其成功探洞=向发送端暖拨 → **发送端 respond_session 被动入池**(Stage A T3 语义)→ 接收端关己侧中继半连 → 发送端在途轮网络面失败 → 重试轮落(被动插入的)暖臂=直连续传。
     「断」从被动变主动,重试/位图续传机制全程既有(§E4 实证)。
- **防振荡**:一次 armed 代际**只轮换一发**;回切后直连若再死,重走穷尽→重新计数→再 armed(中继仍是安全网,绝不乒乓)。
- **匿名卡观感前置**:轮换在接收侧呈现为「可重试轮失败」——下载绑定卡保持 running(既有);**匿名卡依赖 §7-3 幂等重绑票**(非终态同 job_id 来件重绑既有卡,不新增失败卡)。该票因此升为本特性的前置。

### 4.5 明确不做

- 不做「中继期间暂停传输等直连」(轮换=断点续传式,传着切,不停等);
- 不做「中继抢跑」(数据先走中继、直连成再切的激进赛跑)——本版中继线**只预备不承载数据**,直连判决前不启流;
- 不做中继连接入 ctrl 暖池(中继按操作建立、空闲自灭语义不动,配额面除并行预备短暂占槽外零改);
- 不做探洞成功的主动预建之外的任何「隧道预就绪 2.0」(暖池本身就是预建)。
