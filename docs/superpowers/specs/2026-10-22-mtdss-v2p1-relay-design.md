# MTDSS v2-P1 设计:中继兜底与账号预置

> brainstorm 定稿 2026-10-22。v2 总序:P0 账号注册+收尾 → **P1 本设计** → P2 跨会话续传 → P3 Android → P4 Windows UI 打磨 → P5 iOS。

## 1. 意图与为什么

v2 主线是移动端首发(首批用户 = Windows + iPhone(1:1)+ 安卓)。手机在蜂窝网络下几乎全是运营商级 NAT,打洞大概率失败——**没有中继,手机出门产品即不可用**。中继是移动端可用性的前置,同时补全现有桌面用户的直连失败场景。

VPS 现实:阿里云**固定 3 Mbps**。中继的定位由此定为**"从不可用到可用"的兜底**,不是体面通道:50 MB ≈ 2 分钟、1 GB ≈ 45 分钟,这是设计承认并如实呈现给用户的事实。

顺带收口账号模型:今天 `request-code` 把验证码直接放在 HTTP 响应返回(dev 模式),`verify` 对任何新邮箱**自动建号**(`auth.rs` 的 `Err(_) => INSERT` 分支)——门是敞开的。本设计改为**运营者 CLI 预置账号制**(封闭灰度),在商业分发前把门关上。

## 2. 目标

1. 打洞失败时,**已开通中继的账号**自动经服务端中继完成端到端加密传输;未开通账号行为与今日一致(直接失败)。
2. 服务端可运营:按账号开关、按账号限速、按账号月流量配额,全部 CLI 管理,**实时生效**。
3. 限速双端:客户端发送端按分配速率配速(合作式),服务端数据面硬限(权威,不合作也无用)。
4. 计费形态不动:仍走现有固定 3 Mbps,零新增成本;限速/配额/全局上限做成服务端配置旋钮,为将来切按量计费留一键路径。
5. 账号预置 CLI:增删邮箱(增 = 可登录;删 = 挡下次登录,不踢线不杀已建立传输)、列表带用量。
6. 中继对服务器**只见密文**:延续 v1 隐私边界,服务器接触不到文件明文与元数据。

## 3. 非目标

- 不做体面带宽(不切按量、不加服务器)——等真实用量数据再决策
- 不做跨账号/好友传输(两端恒同账号,开关/配额天然覆盖两端)
- 不做 TCP/WebSocket 中继兜底(UDP 被彻底封杀的场景先观察)
- 不做用户自助开关/自助购买配额(纯运营者操作)
- 不动 STUN 与打洞逻辑本体(只在失败分支挂中继)
- 真实 SMTP 邮件(仍在后续里程碑;验证码继续 dev 模式随响应返回)

## 4. 反目标(做了即失败)

- 服务器可解密或窥探中继流量(转发地址与会话计数之外的一切)
- 未预置邮箱仍可登录或自动建号(门必须关死)
- 配额记账丢失/写放大拖垮 3 Mbps 管道
- 改开关/删用户要等旧 token 过期才生效
- UI 把中继暗示成"永远可达"的承诺

## 5. 约束

- 门禁同全局:`cargo test --workspace` + clippy 双平台 + nat-matrix + ui job
- VPS 同机承载信令/STUN/更新源;安全组**新增一个 UDP 端口**(不复用 STUN 3478/3479)
- proto 现有 `Relay` 帧名已被"信令转发"占用(`ws_client_frame::Frame::Relay`),新帧命名必须避开(建议 `RelayAllocate`)
- 现网在跑 1.0.x:新 proto 字段对旧版本**前向兼容**——旧 daemon 忽略 HelloOk 新字段、永不请求中继;旧服务端收到新帧按既有 unknown-frame 语义处理

### 6.1 建造者审查裁定(设计者定,2026-10-22;交接时可否决)

| # | 裁定 | 依据 |
|---|---|---|
| A | `user remove` = **级联硬删**(accounts + 其 devices/codes/relay_config/relay_usage);重加同邮箱 = 全新账号白纸起步 | 封闭灰度阶段运营者心智最简单;软删标志位留僵尸 |
| B | "挡下一次登录"覆盖**四条登录路径**:request-code(404)、verify(401)、refresh 轮换(401——`rotate_refresh` 增账号存在性检查)、WS hello 重连(拒)。已连 WS 不动、已建立 QUIC 不动 | 现状 rotate_refresh 与 ws hello 只查 devices 不查 accounts,"删号"若漏这两处则形同虚设一个月(refresh 有效期 30 天) |
| C | 会话中改配置的语义:**配额耗尽 = 立即杀中转会话**(硬权威);`relay disable` = 杀活跃中转会话(显式运营动作,直连不受影响);限速变更 = 热调令牌桶。服务端持活跃会话注册表(配额本就需要) | 关掉就该停走;disable 与删号(温和)语义不同 |
| D | 数据面**每数据报带会话标签**,服务端逐包鉴权、按包重绑地址(不做首包钉死) | 旗舰场景是蜂窝,45 分钟传输内运营商 NAT 必然重绑;首包钉死会把移动端主场景做成"会莫名断"。客户端侧以自定义 UDP socket 包住 quinn |
| E | 全局带宽上限 = 启动配置(env,改动需重启),默认 **2500 kbps**(3 Mbps 管道给信令/STUN/更新留头寸) | 它是计费层常数,与按量切换同节奏变更 |
| F | `relay enable` 缺省即赋默认值:rate **1024 kbps**、quota **10 GB/自然月**(`user add` 预建 disabled 的 relay_config 行);显式 0 保留"不限"语义 | 防"开了没配 = 隐性不限速吃死共享管道" |
| G | 错误面:中继拒绝(未开通/配额尽/超并发/对端离线)走类型化错误;**配额中断在传输卡片呈终态「中继配额已耗尽」,重试轮不重试分配**;错误码号位留给实现者 | 泛化成网络错误会引发无意义重试轮 |
| H | 计量口径:`bytes_forwarded` = **双向线上字节**(含 QUIC 框架/重传/票据头,服务器看不到也不猜文件字节);配额语义对外表述 = "中继线上流量";冒烟对账容差 = 文件字节 **+10~25%** | 服务器只能诚实地数线上字节 |
| I | 兜底覆盖**全部四个打洞点位**(传输发送回合、常驻接收、ctrl 发起方、ctrl 响应方),统一为 connect-with-fallback 抽象;配速按数据方向归属(数据发送方配速,与谁发起连接无关) | 用户裁定 2026-10-22;ctrl 通道(远端浏览/反向拉取)是 P3 移动端旗舰场景,现在只做传输面 P3 时还得回来补 |

## 7. 架构

### 7.1 服务端(signaling 同进程新模块 `relay`)

- **数据面:单 UDP 端口哑转发**(默认 8788,可配)。两端 daemon 经现有 WS 信令申请中继会话;服务端实时校验(账号开关 + 配额余量)→ 铸**会话票据**(HMAC 防伪,含过期)→ 经信令下发 relay 地址 + 票据给两端。daemon 之间照常跑端到端 QUIC,QUIC 密文报文经中继端口转发,服务器不做任何解密。**每个转发数据报携带会话标签**:服务端逐包鉴权、按包重绑对端地址(蜂窝 NAT 重绑是常态,不做首包钉死);活跃会话注册表承载配额杀会话与限速热调(裁定 C/D)。
- **限速**:每会话令牌桶(取该账号配置);**全局上限**:可配总速率(保护信令管道);**配额**:按账号按自然月累计**双向转发字节**,周期滚动,持久 SQLite;记账节流落盘(内存计数 + 定期/阈值刷库,防写放大)。
- **表**:`relay_config(account_id PRIMARY KEY, enabled, rate_kbps, quota_bytes, updated_at)`;`relay_usage(account_id, period, bytes_forwarded, PRIMARY KEY(account_id, period))`;沿用 CREATE IF NOT EXISTS 惯例。
- **HelloOk** 增 optional 资格字段(enabled / rate_kbps / quota 余量)。
- **认证收口**:`request_code` 先查 accounts(不存在即 404);`verify_code` 删自动建号分支(账号必须已存在,否则 401)。

### 7.2 管理 CLI

新 bin(倾向 signaling crate 内 `[[bin]] mtdss-admin`,或独立 crate——留给实现者)。命令面:

```
mtdss-admin user add <email>            # 预置账号
mtdss-admin user remove <email>         # 挡下次登录(在线设备不受影响)
mtdss-admin user list [--with-usage]    # 列表:开关/限速/配额/本月用量
mtdss-admin relay enable|disable <email>   # enable 缺省赋 rate 1024 kbps / quota 10 GB(裁定 F)
mtdss-admin relay limit <email> <kbps>  # 0 = 不限(受全局上限约束)
mtdss-admin relay quota <email> <GB>    # 0 = 不限
```

直连 SQLite(与 server 并存,WAL);操作幂等,输出面向人读。

### 7.3 客户端(core + daemon + UI)

- **兜底编排(四点位统一)**:传输发送回合、常驻接收、ctrl 发起方、ctrl 响应方四个打洞点位统一走 connect-with-fallback 抽象——打洞重试穷尽且资格在手 → 经 WS 发 `RelayAllocate` → 拿地址 + 票据建立中继路径 → QUIC 照常(manifest/分块/校验/暂停取消全不变,对上层零感知)。远端浏览/反向拉取场景(发起方是接收数据的一方)同样兜底。
- **发送端配速**:按分配速率节流**数据发送方**的新块派发节拍(与谁发起连接无关);接收端不限。
- **UI**:传输卡片加「中继 · 限速」角标(如实呈现"能到但慢");设备页不表现;未开通账号打洞失败仍走今日的错误提示。

### 7.4 验证与冒烟

- 单元:配额滚动与耗尽、令牌桶、票据防伪与过期、认证收口(未预置 404/401)。
- 集成:nat-matrix 增中继场景(强制对称 NAT → 中继路径),**含 ctrl 通道场景**;CLI 全命令对临时库跑通。
- 真机:两台打洞必败环境(如双蜂窝热点)走中继传文件,服务端用量计数与文件字节数对账(容差 = 文件字节 +10~25%,线上字节口径,裁定 H);限速实测生效(会话速率 ≤ 配置);耗尽配额后中继拒绝、下月恢复(测试可调周期)。

## 8. 里程碑切分建议

- **P1a 账号预置 + 认证收口**(CLI + 404/401 改造;独立可交付,先行,老用户无感)
- **P1b 服务端中继数据面**(票据 + 哑转发 + 限速 + 配额记账)
- **P1c 客户端兜底**(四点位统一 connect-with-fallback + 发送端配速 + UI 角标 + nat-matrix;体量大则内切两刀:传输面 / ctrl 面)

## 9. 留给实现者的

- 票据握手具体形状(token 编码、首包映射建立、空闲会话回收超时)
- relay_usage 刷库节流参数与崩溃恢复口径(崩溃丢多少记账可接受,建议 ≤1MB 量级)
- `RelayAllocate` 的 proto 字段号分配与旧版兼容验证方式
- UDP 端口默认值与部署文档(安全组、systemd 不变)
- 每账号并发中继会话上限(建议小值,如 2)
- 打洞失败判定与中继尝试的先后编排细节(与现有重试/退避的衔接)
- CLI 的 `--db` 路径发现(与 server 同配置源)
