## 1. 意图与范围

V3-5 = **P2P 直连通道常驻化**:浏览(ctrl)与传输(transfer)不再逐操作打洞,登录/回前台后预热对全部在线设备,心跳保活,断连自愈,操作复用。

分两阶段,验收线以阶段闸门推进:

- **Stage A|暖浏览(本波主体)**:ctrl 通道 keep-alive + 预热器 + 响应端入池 + 断连自愈。**零协议变更、零平台代码,旧端互通无感**。
- **Stage B|传输复用**:传输作业改在暖连接上开 QUIC 多流(需流类型协议修订)。**Stage A 合并+实机验证通过后启动**;若实测成本失控,回来找用户裁(可能拆 V3-7)。

**Stage A 验收线**:
1. 暖态进目录无打洞(秒开,日志无 punch 编舞);
2. 空闲 >60s 再进目录**不**重新打洞(keep-alive 生效);
3. 对端上线后数秒内暖连就绪(presence 驱动);
4. 断网/换网自愈:网络恢复后下一次浏览无需手动等待(自动重打);
5. 移动端回前台首览 ≤10s(快探+重连+按需打洞叠加;NAT 极端差除外);
6. 大目录首列超时不拆暖连接(后续浏览仍免打洞);
7. 旧端互通:新端预热→旧端照常应答服务(回滚测试);中继兜底连接 60s 自灭不常驻(配额不受暖化影响);
8. 现有全量测试绿(cargo 三平台 + ui + gradlew)+ netns 矩阵绿。

**Stage B 追加验收线**:同一对设备连续两个传输作业,第二个作业无打洞编舞(日志验证)。

## 2. 现状与根因(2026-11-09 代码调查结论)

「目录加载慢,时快时慢甚至失败」根因坐实:**ctrl 池连接无心跳、60s 空闲自杀,冷浏览=全新打洞**。

| 环节 | 现状 | 证据 |
|---|---|---|
| 信令 WS | 已常驻,自动重连(1s×2^n 封顶 30s),presence 事件流现成 | `crates/daemon/src/hub.rs`(run/run_connected/set_device_online) |
| ctrl 连接池 | per-device 缓存 + 单飞锁,命中活连接即复用(快);但 `CTRL_TUNING = keep_alive: None + 空闲 60s 断` → 隔一分钟必死 | `crates/daemon/src/ctrl.rs:54`(CTRL_TUNING)、`ctrl.rs:517`(request 主路径) |
| 打洞编舞 | CtrlConnect→Accept→STUN 候选收集(最坏 ~4s)→候选交换→互拨(预算 10s/轮 2s)→(败)中继兜底分配 10s+互拨 10s。NAT 友好 1-2s,不友好 10-30s 或失败 | `crates/core/src/transport/punch.rs:29`、`crates/daemon/src/flow.rs:206`(STUN 收集) |
| 传输面 | 每个发送/接收作业独立打洞(ConnectRequest→Accept→互拨),连接不复用 | `crates/daemon/src/flow.rs:762`(send_round) |
| 响应端 | 每条 CtrlConnect 起新会话:新端点+新互拨,得到的连接**只 serve 不入池** | `crates/daemon/src/ctrl.rs:985`(respond_session) |
| 流类型 | ctrl 与传输都用裸 `open_bi`/`accept_bi`,无流类型标记——同连接混流会解析打架 | `crates/core/src/transport/ctrl.rs:78/106`、`transfer.rs:372/1008` |

**时快时慢的解释**:快=池命中(60s 内连续浏览);慢=冷打洞(NAT 友好);更慢/失败=NAT 不友好+中继兜底链。**心跳保活直接消灭慢路径的大头。**

## 3. 目标架构

### 3.1 Stage A:暖浏览

**(1) 调优翻转**:`CTRL_TUNING` 开 `keep_alive_interval: Some(15s)`(QUIC PING 帧,几十字节,无业务数据),`max_idle_timeout` 维持 60s(角色转为纯死链检测;QUIC 取两端 min,旧端即 60s,单侧放宽无意义)。数值进既有环境调优旋钮族,实机可调。

**(2) 预热器(warmer,daemon 新常驻任务)**,触发三类:
- **代际建立**:信令连接新代际安装+目录快照就绪(=登录/断线重连/**手机回前台后 WS 重连**——移动端无需任何平台代码,进程恢复→WS 重连→新代际→自动预热)→ 对快照中全部在线设备建连;
- **presence 上线**:`set_device_online(true)` → 补打该设备(带去抖:presence 抖动时合并);
- **断连重打(仅主动侧)**:池内连接 `closed()` → 退避重打(1/2/4…封顶 30s;连续失败进冷却窗,窗内不空转——对称 NAT 等永远打不通的对端靠冷却止损,浏览时按现状按需打洞+中继兜底,正确性不依赖预热)。**重打只由 warm 主动侧(公钥小者)执行**;被动侧检测到 closed 只清自己条目、不主动重打(等对端 warm 或本机浏览按需)——否则双侧各自重打恰好制造 (3) 承诺不会发生的双连,并引发交叉覆写震荡。

登出/被踢 → `CtrlPool::reset`(既有)+ warmer 停(hub 代际拆卸自然触发)。

**(3) 单侧主动,双侧入池;池每设备恰一条,入池留活弃新**:预热主动侧由**公钥字典序**定(小者主动,与 punch.rs 互拨角色同款对称破缺,两端一致推导,不会双连)。被动侧 `respond_session` 改造:accept 得到的连接**入本机池**(serve + 池双职责)——单侧主动即暖双方,反向浏览也免打洞。**入池规则:若池内已有活连接,保留现有、新连接只服务当次不入池**——杜绝「入池覆写→旧连接被端点 drop 杀死→对端 closed→对端重打→再覆写」的震荡环。竞态窗(双侧同时发起各自编舞)允许瞬时双连,由上述规则自然收敛到每侧一条,不追求跨侧互斥。

**(4) 预热编舞 = direct-only 变体;互拨编舞本身零改动**:warm 复用现有 CtrlConnect/CtrlAccept/Candidates 三帧 + 互拨,**只去掉 `connect_with_fallback` 的中继兜底段**(warm 打不通即失败进冷却,不烧服务端中继)。**对旧端零感知**(旧端 responder_loop 本就自动应答任意 CtrlConnect;新端 PING 每 15s 喂旧端 60s 空闲计时器,连接自然长活)。

**(5) 中继连接语义(维持现状,防配额吃穿)**:浏览按需路径的中继兜底**照旧**(打不通才走、按操作建立)。中继连接落在 relay_ep(与直连端点分离,`relay_sock.rs`),**沿用无 keep-alive 调优 → 60s 空闲自灭**,不入 warmer 保活范围——开了直连 keep-alive 后绝不能让 NAT 不友好设备对常驻 7×24 中继会话吃服务器配额;`ConnectOutcome.relay` 在两侧打洞点均可分辨中继/直连,池化与保活策略按此标记分流(直连=暖池+心跳;中继=现状短命)。

**(6) 请求级失败的驱逐语义(暖连接不陪葬)**:现状 `CtrlPool::request` 契约是「请求级失败(或死连接)驱逐后整程重试恰一次」,驱逐=条目 drop=端点 drop=**连接被杀**。暖连接是双侧共享的多流长连接,而 15s `CTRL_SEND_TIMEOUT` 本就是给慢盘大目录枚举留的余量——大目录首列恰是本特性主战场,按现状语义会一次超时就把两端暖连接同时拆掉。改为:**仅连接级错误(QUIC 连接错误/死连接)驱逐+重试;请求超时不拆连接、错误照常上抛**(调用方语义不变,值是否放宽留给实施计划)。

### 3.2 Stage B:传输复用(方向稿,细节随 Stage A 落地后定稿)

- **流类型标记**:双向流首字节流类型(ctrl / 传输控制流),serve 端统一 accept 后按类型分派;数据面 `open_uni` 维持传输独占。
- **会话宣告仍走信令**:ConnectRequest 携带的 target_dir/job_id/policy/display_name 元数据不变;新端发送时若有到对端的暖连接,则跳过打洞段、直接在暖连接上开流;旧对端(不识流类型)回退现状逐作业打洞(版本闸门)。
- **中继兜底不变**:暖连接只优化 P2P 直连;中继会话维持按操作建立(服务端资源与配额考量)。
- **调优合并**:暖连接的 MTU/拥塞参数取 ctrl 与传输兼容值(1452 直连现状即同值,预期无冲突)。

## 4. 语义细节

| 面 | 语义 |
|---|---|
| 心跳 | QUIC keep-alive PING,15s/次/对端,双向各保各的 NAT 映射;成本 ≈ 每对设备每天 <1MB(仅进程存活时) |
| 桌面端 | 登录即暖、常驻保活、断连自愈(daemon 托盘常驻语义不变) |
| 移动端 | 进前台(进程恢复→WS 重连→新代际)批量暖;前台期间复用;进后台进程挂起→心跳自然停→连接死→回前台重建。**不引入前台服务/后台保活**(伞形 §10 反目标维持) |
| 回前台快探 | 挂起中的 WS 是半开连接,靠 keepalive 静默判定最坏 ~60s——不满足「进前台后就建连」。daemon 侧行为变更(仍零平台代码):**任何 IPC 活动时若当前代际疑似陈旧,立即触发 WS 存活探测/重连**,不等 keepalive 计时器;回前台首览时延给及格线(§1) |
| 预热失败 | 不影响正确性:浏览时按现状打洞+兜底;连续失败冷却窗止损 |
| 换网(WiFi↔蜂窝) | 连接死→closed()→退避重打(候选重新收集,新网络新映射) |
| 中继 | 不预热、不常驻;按需兜底打出的中继连接无心跳、60s 自灭(§3.1(5)) |
| 安全 | 暖连接沿用既有 TOFU+pin 证书+白名单,无新信任面;warmer 只对服务器目录内 online 设备发起 |
