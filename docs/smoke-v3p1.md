配套 `docs/superpowers/specs/2026-11-04-mtdss-v3p1-account-security-design.md`(§3 产品语义)
与 `docs/superpowers/plans/2026-11-04-mtdss-v3p1-account-security.md`(Task 14 Step 3 实机场)
的逐项展开;手册风格沿 `docs/smoke-p3.md`/`docs/smoke-p5.md`。自动化面(服务端集成测试、
daemon e2e、三端契约/单测、CI 六 job)已全绿收口,本手册只收**实机判定**:
真邮件收码、双端弹窗、手机扫码登 PC、踢选、任务名两端一致——全部需用户在场。

> ## ⚠️ 执行前置:运营者三件事(runbook-v3 §1-§3,实机场前完成)

> `docs/runbook-v3.md` 执行;升后核验:`curl -X POST .../auth/request-code`

## 2. 测试项清单

> 每项:前置 / 操作 / 预期;记录格式见文末。**实机场:用户在场协作**
> (收邮件/双端操作/扫码/权限弹窗);标注 [操作台] 的条目用户不在场也可由
> 操作者单独执行。

### A. 服务端限流与邮件(实机场:收件需用户看邮箱)

- [ ] **A1 真邮件收码**(实机场)
  - 前置:DM 四 env 就位、SPF/DKIM 已配;VPS 无 dev 回显门;账号已预置。
  - 操作:任一新端登录,输邮箱 → 「获取验证码」;用户查收件箱(注意垃圾箱)。
  - 预期:邮件几分钟内到达,发件人 = 配置的发信地址(别名如「星枢/MTDSS」),
    标题「MTDSS 登录验证码」;正文「你的验证码是 XXXXXX,10 分钟内有效。若非
    你本人操作,请忽略。」;输码登录成功。
- [ ] **A2 429 重试文案**(实机场)
  - 前置:A1 同账号。
  - 操作:领码后 1 分钟内再点一次「获取验证码」(per-email 1/min)。
  - 预期:客户端(UI/CLI)**不闪退、不卡死**,报业务错且文案可读(「获取验证码
    失败」一类中文打头,含服务端「稍后再试」),无裸 HTTP 调试串;约 1 分钟后
    重试可正常领码。
- [ ] **A3 dev 门核验:响应无 code**([操作台])
  - 前置:V3-1 服务端已在位(dev 回显门关)。
  - 操作:`curl -s -X POST https://www.mtdss.top/auth/request-code -H 'content-type: application/json' -d '{"email":"<预置邮箱>"}'`。
  - 预期:200 + `{}`(**响应体无 `code` 字段**);未预置邮箱 404 `unknown account`。
    连打同一邮箱第 2 次 429,响应头带 `Retry-After` 数字、体「稍后再试」。
- [ ] **A4 验证码错/过期路径**(实机场,顺带)
  - 操作:A1 领码后故意输错一次,再用真码。
  - 预期:错码报「验证码错误或已过期」一类业务错不闪退;真码仍可用
    (错满 5 次该码作废是服务端钉面,不故意试到作废)。

### B. 审批链(实机场:双端,用户操作受信端)

- [ ] **B1 新终端弹窗同意路**(实机场)
  - 前置:账号已有一台受信端在线(PC);新端(手机/第二台 PC)走 A1 登录。
  - 操作:新端输码 verify → 受信端(PC)看弹窗「新终端登录请求 ·「XX」请求
    登录你的账号(平台:…)」→ 同意。
  - 预期:新端数秒内翻登录成功(轮询 ≤3s 一拍);受信端弹窗上带 6 位审批码;
    双端设备列表互见新设备。
- [ ] **B2 审批码直输路**(实机场)
  - 前置:同 B1,再发一次新端登录(或另一台新端)。
  - 操作:B1 弹窗上抄 6 位审批码 → **直接在新端**输入提交(桌面 UI「或直接
    输入对方设备显示的 6 位审批码」/CLI 提示口;不等弹窗裁决)。
  - 预期:输码即 settle 登录成功,无需受信端再点同意;输错码报业务错不落会话、
    可重输。
- [ ] **B3 拒绝路**(实机场)
  - 前置:同 B1 再起一次新端 verify。
  - 操作:受信端弹窗点「拒绝」。
  - 预期:新端轮询到终态「登录请求已被拒绝」回表单;不落会话;受信端在线不受
    影响。
- [ ] **B4 超时路**(实机场,可选长等 5 分钟)
  - 前置:同 B1 再起一次新端 verify,受信端**不裁决**。
  - 操作:等待审批 300s 过期。
  - 预期:新端轮询到「登录已超时,请重新发起」回表单;受信端弹窗残留至 TTL
    自灭(300s 窗,裁决时回报 409 面——R6 已知边界,记录现象)。

### C. 踢选(实机场:三端在场最直观)

- [ ] **C1 满员登录 → 踢选 → 被踢端「已被移除」**(实机场)
  - 前置:§1 把某账号 `set-device-limit 2`;该账号两台设备在线(如 PC+手机);
    第三台设备发起登录。
  - 操作:第三台 verify → 出踢选屏「设备数量已达上限」(清单带 名字(平台,
    在线/离线))→ 选一台「移出」。
  - 预期:被踢端**立即**回登录态,横幅「本设备已被移除,请重新登录」,会话清
    (重新登录须走验证码),identity.seed 保留(重登后设备 ID 不变);
    第三台腾位后直入登录成功;双端设备列表同步(被踢端消失)。
- [ ] **C2 离线设备踢选**(实机场)
  - 前置:C1 场,被踢对象选**离线**那台(先退出其登录或断网)。
  - 操作:同 C1。
  - 预期:踢选成功无「目标不在线」类报错;该设备下次上线(重开客户端)直接
    被拒/回登录态(refresh 401 → 连续两次鉴权拒收口,见 §F2)。

### D. 扫码(实机场:PC 出码 + 已登录手机扫码)

- [ ] **D1 扫码全链同意路**(实机场,headline)
  - 前置:PC **未登录**;手机已登录同账号且在线(iOS:「我的」页扫码器;
    Android 本波扫码器顺延 V3-4,用 iOS 或第二台已登录桌面)。
  - 操作:PC 登录屏切「扫码登录」出二维码(iOS 扫码器对准)→ 手机命中后出
    确认弹层(候选名 = PC 主机名/自报名)→ 「同意」。
  - 预期:手机弹层秒回;PC 轮询(2s 档)领票直入设备列表,无需输验证码;
    手机端设备列表出现该 PC;会话落盘,PC 重启保持登录。
- [ ] **D2 扫码拒绝路**(实机场)
  - 操作:重出二维码 → 扫码 → 手机点「拒绝」。
  - 预期:PC 轮询到「登录请求已被拒绝」终态,回登录屏,不落会话。
- [ ] **D3 二维码过期重生成**(实机场,顺带)
  - 操作:PC 出码后放置 ≥120s 不扫(PC 端轮询到过期态);点「重新生成」。
  - 预期:过期后 UI 呈「二维码已过期」;重新生成得**新**二维码(旧码作废,
    扫旧码报「二维码已失效,请重新扫码」),新码可正常走 D1。
- [ ] **D4 非本家码容错**(实机场,顺带,iOS 扫码器)
  - 操作:iOS 扫码器对准任意非 MTDSS 二维码(网页/微信码)。
  - 预期:不跳转不误登录,行内提示「非 MTDSS 登录码…」,取景继续。

### E. 任务名(实机场:两端对照;三形态)

- [ ] **E1 单文件两端同名**(实机场)
  - 操作:PC → 手机发送单文件(如 `报告.docx`),两端传输列表对照。
  - 预期:发起端与接收端任务名一致 = `报告.docx`(非路径串/设备 ID)。
- [ ] **E2 单目录两端同名**(实机场)
  - 操作:发送单目录(如 `项目备份\`)。
  - 预期:两端一致 = `项目备份`(顶层目录名,不含盘符/父路径)。
- [ ] **E3 多项「等 N 项」**(实机场)
  - 操作:一次多选 ≥2 项发送。
  - 预期:两端一致 = 「<首项名> 等 N 项」(N = 所选条目数)。
- [ ] **E4 三端观感一致性**(实机场,顺带)
  - 操作:E1-E3 在 Windows UI、CLI(`mtdss send` 后任务面)、手机端各看一眼。
  - 预期:同一任务三处名字同串(UI/CLI/Android/iOS 消费同一 `name` 下发面)。

### F. 被踢清理(实机场收尾;自动化面已有 e2e,此处验真机行为)

- [ ] **F1 在线被踢即时清**(实机场)
  - 前置:C1 已做过在线踢;此处复核被踢端后续行为。
  - 操作:被踢端尝试继续任何操作(浏览/发文件/看设备列表)。
  - 预期:一律回登录态(会话已清,不复活在线);重开客户端仍登录屏
    (identity.seed 在,重登不重新生成设备身份)。
- [ ] **F2 离线摘除 → 重连拒收口**(实机场)
  - 前置:某设备退出客户端但保留数据(session.json 在盘);VPS
    `device unbind <email> <device_id>` 摘行;再启动该设备客户端。
  - 操作:启动后观察 1-2 分钟。
  - 预期:重连被拒(device not bound)→ 客户端自动收口回登录态
    「本设备已被移除,请重新登录」,不再无限重试空转;identity.seed 保留。
- [ ] **F3 被踢端数据无残留会话**(实机场,顺带)
  - 操作:F1/F2 后查看 `{home}/.mtdss`(Windows `%USERPROFILE%\.mtdss`)。
  - 预期:`session.json` 不在;`identity.seed` 在;登出/被踢不删收件箱历史。

## 3. 故障排查速查(V3-1 增量)

| 现象 | 先查 |
|---|---|
| 收不到验证码邮件 | 垃圾箱;VPS `journalctl -u mtdss-signaling` 有无 DM 发信错误;四 env 是否齐(缺任一 = request-code 500 fail-closed);SPF/DKIM 配置 |
| 领码一律 500 | DM env 未挂上(unit EnvironmentFile 后未 `daemon-reload`/restart);mailer 装配 warn 在启动日志 |
| 领码 429 | per-email 1/min、5/h、per-IP 10/h 档(§A2/A3);等窗口过;**勿**为绕测试开 dev 回显门 |
| dev 门核验发现响应带 code | 服务端仍在 `--dev-echo-code` 形态(unit ExecStart 残留)——**升产后必须摘**,见 runbook-v3 §4 |
| 新端登录无弹窗 | 受信端是否真在线(设备列表绿点);审批 300s TTL 是否已过;旧版客户端(无审批面)先升三端 |
| 扫码后 PC 不动 | 手机端是否已登录(认领须已登录会话);PC 轮询 2s 档等待中属正常;二维码是否过期(D3) |
| 扫码器黑屏 | 相机权限(设置 → MTDSS → 相机);模拟器无摄像头(真机验) |
| 踢选后被踢端没反应 | 被踢端是否真在线(离线踢是懒踢,§F2 重连拒收口);信令 keepalive 口径 ≤60s |
| 任务名两端不一致 | 两端是否都是 V3-1 客户端(旧端不携名,接收端回退自算);对端会话行看 name 字段 |
