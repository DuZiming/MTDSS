**观察口径(日志面)**:关键行清单——`ctrl 会话已打通(from=…, relay=false|true)`
(info;打洞编舞完成,暖态浏览**缺席**即验收线 1/2 主证)、`warm 预热成功,挂 death
watcher`(debug;预热就绪)、`warm 断连/失败重打退避`(info;自愈)、`ctrl 池已有
该对端活连接,留旧弃新(decline)`(info;入池纪律)、`ctrl 复用连接请求失败但连接
仍活,验证缝:另打新连接重发恰一次`(warn;僵尸自愈,§B3)、`信令已上线`(info;
WS 代际安装,快探重连后 ~2s 内重现)、code 3 = RPC「信令未在线,无法发起控制通道」
(快错窗,§B5)。QUIC PING 帧不上日志——keep-alive 生效以「无重打日志 + 秒开」为证。

## 2. 测试项清单

> 每项:前置 / 操作 / 预期;记录格式见文末。**实机场:用户在场协作**;标注 [操作台]
> 的条目用户不在场也可单独执行。建议顺序:**§A → §B → §C → §D**(§D 需换包,收尾做)。

### A. 暖浏览核心链(实机场:PC ↔ MIX 3;验收线 1/2/3)

- [ ] **A1 暖态进目录无打洞 = 秒开**(实机场,headline;验收线 1)
  - 前置:双端登录在线,等 ≥15s(预热窗:PC 日志见每台在线对端一行 `warm 预热成功`)。
  - 操作:①PC 设备页点 MIX 3 进顶层;②连续下钻 2-3 级目录;③同时开 PC daemon
    日志窗(或事后 `--log-file`)搜「会话已打通」。
  - 预期:①②每次进目录**秒开**(无打洞等待体感);③**浏览期间无新增「会话已打通」**
    (池命中;若有则记录时间戳——只允许登录后首批预热各一条)。[反向:从 MIX 3
    浏览 PC 同样秒开——响应端入池,单侧主动暖双方。]
- [ ] **A2 空闲 >60s 不重打**(实机场,headline;验收线 2)
  - 操作:A1 后**闲置 >70s**(不碰两端 App);再从 PC 下钻 MIX 3 一层;看日志。
  - 预期:仍秒开;**无新「会话已打通」**(keep-alive 15s PING 喂着两端 60s 空闲计时
    器,连接长活)。若见重打日志 = 验收线 2 红,记录两侧日志时间戳。
- [ ] **A3 对端上线数秒暖连 + 反向免打洞**(实机场;验收线 3)
  - 操作:①MIX 3 杀 App → 等 PC 设备页其行翻灰;②重开 MIX 3 App;③PC 日志窗盯
    `warm 预热成功`;④就绪后 PC 立即浏览 MIX 3;⑤反向从 MIX 3 浏览 PC。
  - 预期:②③**重开后台词上线后数秒内**(去抖 750ms + 打洞 1-3s)PC 日志出现
    `warm 预热成功`(对 MIX 3 设备);④此时浏览秒开无编舞;⑤反向浏览同样秒开
    (B 侧池已被 respond 入池,反向免打洞——T3 语义的实机面)。

### B. 自愈与快探(实机场;验收线 4/5 + 执行期语义三条)

- [ ] **B1 断网/换网自愈**(实机场,headline;验收线 4)
  - 操作:①暖态(A1 前置)→ MIX 3 关 WiFi(或开飞行模式)→ PC 看 presence 翻灰;
    ②MIX 3 回开 WiFi(同网或换热点=换网形态均可);③PC 日志盯 `warm 断连/失败
    重打退避` 与 `warm 预热成功`;④就绪后 PC 立即浏览 MIX 3。
  - 预期:③重打日志按退避梯出现(1/2/4s 起,连败 3 次进 5min 冷却窗——正常自愈
    1-2 跳内成功,冷却窗只在永远打不通的对端止损,§G1);④网络恢复后**下一次浏览
    无需手动等待**,秒开或一次编舞内通(≤3-8s,NAT 视)。
- [ ] **B2 移动端回前台首览 ≤10s**(实机场,headline;验收线 5)
  - 操作:①MIX 3 App 进后台 → 屏息/切走 ≥2min(连接必死窗);②回前台,立即点
    PC 设备行进顶层;③计时首屏;④iPhone 同型一轮(若装 V3-5 包)。
  - 预期:**回前台首览 ≤10s**(快探:回前台首点触发陈旧代际 kick + 1s 首跳重连 +
    预热批量暖 + 按需打洞叠加;NAT 极端差除外)。记录实际值;超 10s 记录两侧日志
    (快探 kick 指纹 = 「信令已上线」在首览后 ~2s 内重现)。
- [ ] **B3 对端重启僵尸验证重拨**(实机场,headline;执行期语义)
  - 前置:暖态(A1);MIX 3 允许被杀(adb 可用)。
  - 操作:①PC 暖态浏览正常;②**硬杀 MIX 3 App 进程**(`adb shell am force-stop`
    或系统强停——静默死亡,不发告别帧)→ 秒级重开 App;③重开完成后 PC **立即**
    浏览 MIX 3(命中池内僵尸连接的窗口);④首次浏览完成后**再次**浏览。
  - 预期:③首次浏览**慢但成**:命中的僵尸连接烧满 15s 请求上界后,验证缝另打新
    连接重发恰一次——总时延 ≈ 15s + 打洞 1-8s,**请求最终成功**(不报错不挂死;
    日志指纹 `ctrl 复用连接请求失败但连接仍活,验证缝:另打新连接重发恰一次`);
    ④**第二次浏览秒开**(验证缝已驱旧换新,池内是健康连接;不再见新的 decline/
    验证缝指纹)。注:慢请求可能在对端执行两次(幂等读面,无害;写面
    语义与波前基线同型)。
- [ ] **B4 健康链路不误 kick(Pong 喂钟)**([操作台];执行期语义)
  - 操作:①双端登录在线后**闲置 5-10min**(期间只偶发点开设备页刷新);②PC 日志
    搜「信令已上线」出现次数。
  - 预期:闲置期间**无周期性重连**(Pong 每 ≤20s 喂陈旧时钟,25s 阈只对真陈旧/
    半开生效;若见每 ~25-30s 一轮「信令已上线」= 误 kick 回归,记录)。
- [ ] **B5 kick 后 code-3 快错窗(接受行为观察)**(实机场,顺带;执行期语义)
  - 操作:①制造一次真陈旧 kick(如 B2 的长时间挂起回前台,或信令网抖);②kick
    后 ~1.5-2s 窗内立即在 PC 触发一次需信令的操作(如刷新设备列表)。
  - 预期:**快错而非挂死**——RPC 返回 code 3「信令未在线,无法发起控制通道」
    (~1.5-2s 内),UI 呈错可重试;1s 首跳重连落地后重试即成。**本窗为裁定接受的
    产品行为**(快错+客户端重试),记录体感即可,不算失败。

### C. 超时与大目录(实机场;验收线 6)

- [ ] **C1 大目录首列超时不拆暖连接**(实机场,headline;验收线 6)
  - 前置:**PC 侧**备大目录一枚(≥2 万项;资源管理器批量复制最省事;debug 构建
    枚举更慢,若仍 <15s 则改机械盘/网络路径垫慢=构造触发面;触发不了则记录
    跳过——语义已由自动化面 e2e 钉死);双端暖态。
  - 操作:①**MIX 3 浏览 PC**,进入该大目录(首列必超 15s 请求上界);②看 MIX 3
    报错与 PC daemon 日志;③等 ~30s 后 MIX 3 再浏览 PC 一个**小**目录;④再回
    大目录。
  - 预期:①首列超时呈「无法加载目录」类诚实报错(慢枚举=预期触发面);②PC 日志
    指纹 `ctrl 复用连接请求失败但连接仍活,验证缝:另打新连接重发恰一次` → 随后
    `ctrl 验证缝新连接同样失败,按 Surface 上抛原始错误,暖连接不动`(验证新连接
    同样超时=慢盘余量真耗尽,上抛原始错误、暖连接一指不动);③**后续小目录浏览
    秒开无编舞**(暖连接未陪葬——验收线 6 主证);④大目录仍超时(慢盘面,§G2 记录
    量级)。

### D. 旧端互通与回滚(实机场;验收线 7)

- [ ] **D1 新端预热→旧端照常应答(新旧混跑)**(实机场,headline;验收线 7)
  - 前置:MIX 3 **退回 V3-4 旧 APK**(adb install -r;PC 保持 v3p5 新端);双端登录。
  - 操作:①等 PC 预热窗(对旧端 MIX 3 打 warm 编舞——旧端 responder 自动应答,
    零感知);②PC 浏览 MIX 3 顶层与下钻;③**闲置 >70s 再浏览**(A2 同款);④MIX 3
    (旧端)反向浏览 PC。
  - 预期:②③**全部照常**:秒开、无重打(新端 15s PING 喂旧端 60s 空闲计时器,
    旧端连接同样长活——旧端零改动即享受保活);④旧端→新端逐操作打洞基线照旧
    成功,新端正常应答。功能抽测:收发一枚文件、删除门语义不变。
- [ ] **D2 回滚互通(两端全退旧版基线)**(实机场;验收线 7 回滚测试)
  - 操作:①PC 换回 V3-4 构建(daemon+UI 旧产物),MIX 3 保持旧 APK;②双端登录
    跑基线抽测:互浏览、收发一枚、空闲一分钟再浏览(应见旧基线行为:隔分钟
    重打洞——这是**预期**,不是回归);③观察无异常后 PC 换回 v3p5。
  - 预期:旧-旧组合功能零回归(逐操作打洞、60s 空闲断——基线语义如实重现);
    本项确认「回滚无死角」,新端可随时安全退场。
- [ ] **D3 中继兜底 60s 自灭不常驻**(实机场,NAT 差网;验收线 7,观察项)
  - 前置:需打洞失败环境(对称 NAT 侧/严苛路由;双端暖态在打洞必败对上预热应
    见 `warm 预热失败,进退避` 进冷却——正确止损)。
  - 操作:①PC 对该对端发起浏览(按需路径走中继兜底);②日志确认
    `ctrl 会话已打通(from=…, relay=true)`;③**闲置 >70s** 再浏览同一对端;④看
    服务器中继会话面(可选项:VPS 侧连接数)。
  - 预期:③再浏览出现**新一条** `relay=true` 打通日志(旧中继连接 60s 空闲自灭,
    未复用未保活);④无 7×24 常驻中继会话,配额不受暖化影响。打洞必败对**不**
    持续烧中继(warmer 冷却窗止损)。NAT 环境不可得则记录跳过,归冒烟场代跑。

## 3. 故障排查速查(V3-5 增量)

| 现象 | 先查 |
|---|---|
| 浏览回不到秒开(每浏览都打洞) | 双端日志有无 `warm 预热成功`;池条目是否被 `留旧弃新` 挡过(僵尸占位 → §B3 指纹应已自愈);keep-alive 值(env 旋钮) |
| 空闲 >60s 后重打了 | 是否踩两端 idle min(一端引擎未升=旧端无 PING 发出面,新端单侧 PING 仍应保活——若双端均 v3p5 仍断,记录日志=回归);QUIC PING 不上日志,以重打指纹为准 |
| 回前台首览 >10s | 快探是否 kick(「信令已上线」时序);预热批量是否完成;NAT 形态(极端差=口径除外,记录) |
| 对端重启后浏览报错(非慢但成) | 应为 §B3 慢但成;若直接报错,查验证缝指纹缺位(回归即报);对端是否二次掉线 |
| 长闲置后设备页被周期性刷新 | 误 kick 回归嫌疑(§B4);查「信令已上线」频次与 Pong 喂钟 |
| 大目录超时后小目录也慢 | 验收线 6 红嫌疑(暖连接被拆);查验证缝/「暖连接不动」指纹 vs 驱逐指纹 |
| 中继会话常驻不掉 | §D3 红;确认该连接是否被误入 warm 保活(中继条目带 relay 标记,不入保活) |

### 记录格式
