# M3c 冒烟测试手册

配套 `docs/release-checklist.md`「M3c 手动冒烟」使用;本文覆盖 M3c 增量面与逐项测试判定标准。环境要求与部署步骤(信令/STUN 服务端、客户端构建、多 `MTDSS_HOME` 隔离)**沿 `docs/smoke-m3a.md` §1–§2**,不重复。

M3c = 传输与操作:CLI `put/get/cp/rm/mv`(定向/冲突三档/四态 cp/回收删除)、UI 冲突对话框、粘贴与拖拽(窗内拖/OS 拖入/拖出落点矩阵)、传输面板(暂停/取消/卡片)、通知双侧、删除与回收、托盘计数,以及 M3b 终审携带件回归(C:foo、`.MTDSS` 大小写、登出拆卸 ctrl、devices 现拉、StatusBar 加载态)。M3a/M3b 已验的托盘基础面/浏览面不重复覆盖。

## 1. 环境与准备(沿 M3a,增量如下)

1. 服务端照 M3a §2.1(回环信令 + STUN,`smoke\tls` 开发证书);客户端照 M3a §2.2 `cargo build -p mtdss-cli -p mtdss-daemon`。
2. **先退出全部旧 mtdssd 进程**(增量,必做):托盘图标右键「退出」或任务管理器结束所有 `mtdssd`。原因:①托盘 tooltip 计数、传输 jobs 面只在**新编译** daemon 上存在(旧实例是 M3c 之前的行为);②旧实例占着 IPC socket 会让新 daemon 起不来。若 cargo 链接时报 `mtdssd.exe` 被占用,即仍有旧实例存活。
3. **同一邮箱**登录三台「设备」(第三个 MTDSS_HOME 供 A→B 用):
   - 设备 A(本机,带托盘):`$env:MTDSS_HOME = "<repo>\smoke\home_a"` 后 `mtdss login ... --name dev_a`;
   - 设备 B(无头):另开终端 home_b 环境 `target\debug\mtdssd.exe --no-tray --log-file smoke\home_b\d.log`,再 `mtdss login ... --name dev_b`;
   - 设备 C(无头,A→B 的第二跳):home_c 环境 `mtdssd --no-tray --log-file smoke\home_c\d.log` + `mtdss login ... --name dev_c`。
   - 三侧 `mtdss devices` 互见且 `online=true`。
4. UI:`$env:MTDSS_HOME` 指向 **home_a** 后 `cd ui ; npm install(首次) ; npm run tauri dev`。窗口出、登录态正常、三台在线。(终门禁另含 `npm run build`,冒烟不强制。)
5. 预置材料:本机 `smoke\mat\` 备几个数 MB 文件 + 一个含子目录的嵌套树(目录传输/嵌套同名用);B 备两个空目录(`C:\mtdss_in_b` 定向目标、`C:\mtdss_in_b2` 同设备复制糖目标——**同设备 cp/mv 目标须已存在**,ctrl 直改不自动建目录),C 备一个空目录(`C:\mtdss_in_c`)。
6. 判定基线:以下各步骤的「期望结果」均以 §1 环境为前提;执行中失败先查各 daemon `--log-file` 与 CLI 终端输出。

> 提醒:`.mtdss` 隐藏收件区不出现在列表(M3a 起设计保留段),顺带核对。

## 2. 测试项清单(逐项判定标准)

> 建议顺序执行;每项记录 通过/失败 + 现象一句话;失败时附 daemon `--log-file` 与 CLI 终端输出。
> CLI 命令均在 **home_a** 环境终端执行(操作 dev_b/dev_c);标注「home_b/home_c 终端」的除外。

### A. CLI 操作面(`put/get/cp/rm/mv`)

- **A1 put 定向落盘**:`mtdss put dev_b:C:\mtdss_in_b smoke\mat\f1.txt smoke\mat\sub`。判定:阻塞至终态后输出「传输完成(N 个文件,共 M 字节)」,退出码 0;dev_b 的 `C:\mtdss_in_b` 出现 `f1.txt` 与 `sub\` 整树,内容与源一致;dev_b **默认收件目录无新增**(定向语义)。
- **A2 put 冲突 ask 问询**:原样重跑 A1(目标已有同名)。判定:打印「目标处已存在 N 个同名条目:」+ 逐条 rel(>20 条截断计数)+ 末行「[s] 全部跳过  [o] 全部覆盖  [c] 取消」与 `> ` 问询;答 `s` → 冲突项不落盘、其余正常、完成文案仍 done;答非法串(如 `x`)→ **重问**;原样再跑答 `c`(或 `q`,大小写不敏感)→ 输出「已取消」、退出码 **0**、不发起传输(目标无变化)。
- **A3 put `--conflict skip/overwrite`**:A2 场景分别加 `--conflict skip` 与 `--conflict overwrite`。判定:skip=冲突项全部跳过、无问询;overwrite=目标同名文件内容翻新、**无** ` (1)` 改名、无问询。
  - 附(嵌套安全网):put 一个目录,其**子目录内**与目标已有条目同名(顶层不冲突)。判定:无问询(预扫仅顶层,V1 限制),落盘时嵌套同名自动改名 `名称 (1)`,不覆盖不报错。
- **A4 get `--to` 本机**:`mtdss get dev_b:C:\mtdss_in_b\f1.txt --to C:\temp\getout`。判定:文件落 `C:\temp\getout\f1.txt`、内容一致、**源仍在 dev_b**;目标目录已有同名时同样走 A2/A3 的问询/策略;`mtdss get dev_b:... --to` 指向不存在目录 → 自动建出。
- **A5 cp 四态**:
  - ① download 糖:`mtdss cp dev_b:C:\mtdss_in_b\f1.txt --to C:\temp\getout` ≡ A4(远端→本机落盘)。
  - ② upload 糖:`mtdss cp smoke\mat\f2.txt --to dev_b:C:\mtdss_in_b` ≡ A1(本机→远端)。
  - ③ 同设备糖:`mtdss cp dev_b:C:\mtdss_in_b\f1.txt --to dev_b:C:\mtdss_in_b2`。判定:**即时完成**(同机 ctrl 复制,不经传输面、无卡片);有同名时先提示「目标处已存在 N 个同名条目;同机复制冲突由接收端自动改名(--conflict 不适用)」,再输出「同机复制完成:N 项」;目标处副本在,同名自动改名,源仍在。附:目标目录不存在 → 报 NOT_FOUND、退出码 1(同机糖不自动建目录,与传输面不同);`--to` 指向文件 → 报「目标不是目录」。
  - ④ **A→B(三 daemon)**:`mtdss cp dev_b:C:\mtdss_in_b\f1.txt --to dev_c:C:\mtdss_in_c`。判定:阻塞至终态「传输完成」;dev_c 盘见文件、dev_b 源仍在;**dev_a 本机(home_a 收件目录/各盘)无数据落地**——中转不经操作端。
  - 补(拒答态):源与目标都在本机 `mtdss cp C:\a --to C:\b` → 报「cp 的源与目标都在本机:请直接用系统复制(cp 只管经设备的复制)」,退出码 1。
- **A6 rm 静默回收 / 永久旗**:`mtdss rm dev_b:C:\mtdss_in_b\f1.txt`。判定:**无任何确认问询**(可回收两端静默),输出「删除完成:1 项(已入回收站)」、退出码 0;B 侧回收站可见该文件(B 本机即本机回环,直接开回收站看)。`mtdss rm dev_b:... --permanent` → 「删除完成:1 项(永久删除)」,同样无问询、不经回收站。
- **A7 rm 确认梯(可选,环境依赖)**:仅当对端**回收站不可用**时触发(Windows 回环难构造;有 Linux/macOS 对端且其回收不可用时测,构造不出记 SKIP——CI 注入面已覆盖逻辑)。判定:报文含「回收站不可用: …」后出 `确认永久删除?[y/N]`;答 `y` → 重发 force,「删除完成:N 项(永久删除)」;答 `N`/直接回车 → 「已取消」、退出码 **0**。
- **A8 rm 部分失败**:`mtdss rm dev_b:C:\mtdss_in_b\f1.txt dev_b:C:\mtdss_in_b\nope.txt`(一真一假)。判定:真实项已删;退出码 **1**;stderr「删除部分失败:…nope.txt(NOT_FOUND: …)」逐条点名;批不半途弃废(成功项已生效)。
- **A9 mv 同设备 + 跨设备指引**:`mtdss mv dev_b:C:\mtdss_in_b\sub --to dev_b:C:\mtdss_in_b2` → 「移动完成:1 项」,`sub` 整树移入(改名即移动);目标撞既有**文件** → 静默覆盖(V1 限制,§0)。目标目录不存在 → 「移动完成:0 项」+「移动部分失败:…(NOT_FOUND: …)」逐条点名、退出码 1(批不弃废;同机糖目标须已存在,与 A5③ 同口径)。跨设备 `mtdss mv dev_b:... --to dev_c:...` → 「mv 仅支持同设备移动:源设备「dev_b」与目标设备「dev_c」不同,跨设备请用 cp」、退出码 1、**不发 RPC**。
- **A10 `C:foo` 拒绝(携带件回归)**:`mtdss put dev_b:C:foo smoke\mat\f1.txt`。判定:报「裸路径(盘符形态)缺少设备段:…」、退出码 1(单字母设备段+路径无盘符识别为盘符相对路径误输);`C:\x` 与 `C:` 正常形态不受影响(A1/A5 已隐含)。
- **A11 `.MTDSS` 大小写滤除(携带件回归)**:本地造 `smoke\mat\case_t\.MTDSS\x.txt` 与 `smoke\mat\case_t\y.mtdss-part`,`mtdss put dev_b:C:\mtdss_in_b smoke\mat\case_t`。判定:落盘的 `case_t` 内**无** `.MTDSS`(大小写不敏感滤除)、`y.mtdss-part` 正常上传(后缀名不误伤,精确匹配语义保留)。
- **A12 卷根/.mtdss 操作对象拒绝(终审修复)**:`mtdss rm dev_b:C:\ --permanent`(与裸 `dev_b:C:`)→ 拒绝执行,退出码 1,报文含「拒绝以卷根为操作对象」(INVALID_PATH),B 侧 C 盘完好;`mtdss mv dev_b:C:\mtdss_in_b\f1.txt --to dev_b:C:\` 与同设备 `cp … --to dev_b:C:\` 同拒;操作对象落在 `.mtdss` 保留段(如 `mtdss rm dev_b:C:\mtdss_in_b\.mtdss`,大小写变体 `.MTDSS` 同)→ 报「拒绝以 .mtdss 保留段为操作对象」;正常路径的 rm/mv/cp 不受影响(A5③/A6/A9 已隐含)。

### B. 冲突对话框(UI,dev_a 浏览 dev_b)

- **B1 单条冲突两键**:dev_b 目标目录预置同名旧文件 → 对该文件粘贴上传。判定:弹「存在同名冲突」对话框,单条正文「目标文件夹已包含「f1.txt」,要如何处理?」+ 源/目标双列元数据(类型+大小+目标 mtime)+ **「跳过」「覆盖」二键**;点「跳过」→ 目标保持旧内容;点「覆盖」→ 内容翻新、无 ` (1)`;**全部决完自动开传,无确定键**。
- **B2 批量四键与「全部键只作用未决」**:预置 ≥2 个同名 → 对话框四键:跳过/覆盖/**全部跳过(N)/全部覆盖(N)**(N=当前未决数,实时缩)。判定:先点某行「跳过」再点「全部覆盖」→ 该行保持「将跳过」,其余翻「将覆盖」(全部键只作用剩余未决项)。
- **B3 目录恒合并不弹框**:上传一个目录,目标处已有**同名目录**(内容不同)。判定:**不弹**对话框,目录合并落盘(两侧内容并集,同名文件按决策走 B1/B2)。
- **B4 类型不匹配行注**:构造「目标=文件 vs 源=目录」同名 → 对话框该行加注「类型不匹配(文件/文件夹),覆盖只清除文件型占用,目录占用将自动改名」;选覆盖执行不报错不 panic(目录占用落自动改名)。
- **B5 Esc/遮罩取消 + 模态占线**:对话框开着按 Esc 或点遮罩 → 整批取消、无传输发起;同态下按 Del/Ctrl+X/Ctrl+C/Ctrl+V、从 Explorer 拖入文件 → **全部无反应**(模态门,不叠确认框、不顶掉待决批次)。
- **B6 预扫失败中止整批**:粘贴前一瞬杀掉 dev_b daemon(或在 home_b 终端 Ctrl+C)→ 点粘贴。判定:提示条「无法检查目标文件夹:<报文>」,**整批不发起**(无卡片、目标无新条目);恢复 daemon 后重试正常。

### C. 粘贴与拖拽(UI)

- **C1 Explorer 复制 → MTDSS 粘贴上传**:本机 Explorer 选文件 Ctrl+C → MTDSS 进入 dev_b 某目录 Ctrl+V(或右键/工具栏粘贴)。判定:上传卡片出现(event 驱动),落盘正确;当前位为设备根卷列表时粘贴 → 提示「设备根卷列表不是文件夹,请先进入一个文件夹再粘贴」。
- **C2 MTDSS 复制 → 粘贴本机(download)**:dev_b 选条目 Ctrl+C → 树/面包屑切到本机某目录粘贴。判定:「下载」卡片,文件落本机所选目录、远端源仍在。
- **C3 MTDSS 复制 → 粘贴另一远端(A→B remote_copy)**:dev_b 复制 → 进 dev_c 目录粘贴。判定:「跨设备复制」卡片;dev_c 落盘、dev_b 源仍在、**本机无落地**。
- **C4 同设备粘贴(device_copy,无弹框)**:dev_b 内复制 → 粘贴到 dev_b 另一目录。判定:**无冲突对话框**(ctrl 通道直改,即时完成、不建卡片);copy 语义撞名自动改名 `name (1)`;Ctrl+X 剪切后粘贴 = move(撞名**文件**静默覆盖,V1 限制),源消失、内部剪贴板清空(条目 dim 视觉消失)。失败面:device_copy 报错 → toast「设备内复制失败:<报文>」。
- **C5 剪切上传删源(put 的 cut 面,仅 UI)**:本机 Explorer 场景改用 MTDSS 内部:先让本机条目进内部剪贴板(浏览「本机」设备 Ctrl+X)→ 粘贴到 dev_b 目录。判定:上传完成后**本机源进回收站**(尽力回收)、目标在;若粘贴到当前目录外的位置后取消传输,源不删。
- **C6 窗内拖(树节点/面包屑)**:dev_b 条目按住(≥4px 启动)拖到侧栏 dev_c 某文件夹节点(高亮)→ 松开 = **跨设备复制**(卡片,数据不经本机);拖到侧栏 dev_b 自身另一文件夹节点 = **移动**(同设备,等 C4 move);拖到面包屑某段/当前目录视图 = 粘贴同语义;拖回自身当前目录 = 无操作;**设备根节点(卷列表位)不亮不收**;任何拖拽不改键(修饰键无义)。
- **C7 OS 拖入**:Explorer 拖文件进 MTDSS 窗口(当前位为远端目录)→ 松开 = 上传,冲突走 B 组对话框;当前位为设备根卷列表 → 无反应;对话框开着拖入 → 无反应(B5 模态门)。
- **C8 下载到本机选择器(右键/菜单项 → OS 目录对话框)**:dev_b 选条目(文件或目录均可)→ 右键 → 「下载到本机…」。判定:弹出**系统原生文件夹选择对话框**(tauri pick_folder;无其他中间步骤)→ 选定目标目录 → 立即开始 download 落所选目录(卡片出现、文件落位);选定目录已有同名 → 冲突走 B 组对话框;Esc 取消选择器 → 不发起传输。

### D. 拖出落点矩阵

> 按 Task 10 spike 结论:普通资源管理器窗口落点**留 V1**(9 类目标 × 10 次 = 90/90 正确;主路 UIA 全路径 ≈70ms,异常兜底全扫 ≈0.2s)。拖出**不交付数据**——落点只触发本机 download,系统资源管理器不经手。

- **D1 桌面落点**:拖 dev_b 条目出窗口到桌面空白处 → 松开。判定:该条目 download 到桌面(卡片可见、文件出现),光标离窗时呈 grabbing 态。
- **D2 普通资源管理器窗口落点**:开一个真实文件夹窗口(如 `C:\temp\dropout`)与一个**驱动器根窗口**(地址栏显示「本地磁盘 (C:)」),分别拖条目到其上松开。判定:两种窗口都落入对应目录(窗口类 CabinetWClass → UIA 地址栏 → 路径;驱动器根显示名有回退);解析在亚秒级(≈70ms)。
- **D3 库/此电脑/回收站**:拖到「图片库」/「此电脑」/「回收站」窗口松开。判定:提示条「请拖到桌面或使用下载到本机…」,无落盘、无报错(非文件系统视图设计性 Unresolvable)。
- **D4 第三方窗口/任务栏/MTDSS 自窗**:拖到浏览器/任务栏/MTDSS 自己的窗口松开。判定:同 D3 提示条;**确认不向这些窗口交付任何数据**(剪贴板/OLE 无 MTDSS 数据)。
- (探针复核,可选:`cargo test --manifest-path ui/src-tauri/Cargo.toml manual_probe -- --ignored --nocapture` 在真实桌面逐类打印解析结果,预期与 D1–D4 一致。)

### E. 传输面板与控制(UI)

- **E1 卡片聚合**:同时起 ≥2 个传输(两次粘贴,或一上传一下载)。判定:窗内右下角卡片堆叠、各自独立;每卡 = 方向字形(↑/↓/⇄/⇇)+ 类型标签(上传/下载/本机复制/跨设备复制/接收)+ 状态标签 + src→dst 摘要 + 聚合进度条 + 文件 N/M + 速率 + 暂停/继续 + 取消;接收侧(incoming)匿名卡在无 job_id 时按不确定态呈现。
- **E2 暂停/继续**:大文件传输中点「暂停」。判定:进度停走(收端同步挂起)、按钮翻「继续」、状态标签「已暂停」、该卡速率退出状态栏汇总;点「继续」→ 续传至完成、内容校验一致。
- **E3 取消与 download 取消传播**:点「取消」→ 卡转「已取消」留置(带提示),× 关闭消失;对进行中的 **download** 点取消 → A 侧卡转已取消,且 home_b 终端的 `--log-file` 在数秒内不再出现新的传输轮活动(取消经 ctrl 传播到源端,发送端不重试到天荒地老)。
- **E4 done 5s 自隐**:小传输完成 → 「已完成」卡 5 秒后自动消失。
- **E5 failed 留置**:传输中杀掉对端 daemon → 「失败」卡留置、带 error 原文 + 「该传输未完成,可重新发起」;× 手动关闭。
- **E6 remote_copy 拒暂停**:A→B 跨设备复制卡点「暂停」→ toast「传输操作失败」(daemon 拒绝如实呈现,code 1),卡片状态不变、传输继续。
- **E7 状态栏速率与计数**:传输中状态栏出现「↓ X MB/s(N 个传输中)」(全角括号),N=非终态作业数、速率仅汇总 running 作业;全部终态后该段消失。
- **E8 托盘 tooltip 计数(前提:§1 已退出全部旧 mtdssd)**:起 N 个传输 → 悬停托盘图标,tooltip =「MTDSS — N 个传输中」;全部终态 → tooltip 回「MTDSS」。
- **E9 排队/重试间隙暂停不丢(终审修复面)**:起大下载 #1(dev_b → 本机,数 MB 以上、传输需持续数秒);传输中立**即**起下载 #2(同源同目标,如 `mtdss cp dev_b:C:\mtdss_in_b\big.bin --to C:\temp\getout`)→ #2 卡片 running 但无进度(同一接收方串行收件,ConnectRequest 排队 = 暂停先于轮绑定的窗口,与网络级重试间隙同一路径)。判定:趁 #1 未完对 #2 点「暂停」→ #1 完成后 #2 开轮时**必须保持冻结**:卡片 paused、bytes_done 不爬升、速率退出状态栏汇总(修复前:新轮全新暂停门,暂停丢失,全速传输 + 卡片 paused 假态);点「继续」→ #2 续传至完成、内容一致。(真·网络断流重试间隙回环不可构造,本项以串行排队窗口覆盖同一「暂停先于绑定」路径;若 #2 源端 Accept 等待超窗失败重试,重来的绑定同样受检。)

### F. 通知(被写方,双向各验一次)

> 通知由**被写方 daemon** 发出(系统通知 + event.notify);被写方有 UI 窗口时另见窗内 toast。无通知总线的真无头端(Linux 无 dbus)仅日志——回环 Windows 不适用,公网真机段验证。

- **F1 上传方向(被写方 = B)**:A put/粘贴一批到 dev_b 落盘 ≥1 文件 → 桌面出现系统通知,标题「MTDSS」、正文「«dev_a» 向 C:\…写盘目录… 写入 N 个文件」(回环下通知来自本机 mtdssd.exe;B 无 UI,无窗内 toast 属预期)。
- **F2 下载方向(被写方 = A)**:A get/cp `--to` 本机落盘 → 系统通知同文案 + **A 的 UI 窗内 toast** 同文案;连发多批 → toast 队列保持 ≤3(最旧被顶)、5s 自隐。
- **F3 全 skip 不通知**:同内容重传且全部跳过(0 落盘)→ **无**通知(「写入 0 个文件」是噪音,设计)。

### G. 删除与回收(UI)

- **G1 UI 静默回收**:浏览 dev_b 选条目按 Del(或右键删除)。判定:**无任何确认弹窗**,条目消失、选择清空、列表刷新;B 侧回收站可见(可回收 → 两端完全静默)。
- **G2 UI 回收不可用确认梯(环境依赖,构造不出记 SKIP)**:对端回收不可用时报文含标记 → 弹「永久删除」确认框:「回收站不可用,无法移入回收站。是否永久删除所选 N 项?此操作不可撤销。」;点「永久删除」→ force 整批重发。
- **G3 UI 离线删除友好文案**:杀 dev_b daemon → 删除远端条目。判定:瞬时提示「设备离线,无法完成操作」,不炸界面、不清其他状态。
- **G4 UI 部分失败**:删一真一假(先造一个已被他端删掉的 stale 选择)。判定:提示条显示失败报文(6s 自隐);成功项已生效。(已知 V1 限制:失败时清空全部选择、只显首条失败报文。)

### H. 携带项回归(M3b 终审清单)

- **H1 登出拆卸 ctrl**:双 daemon 浏览/传输可用态 → home_a 终端 `mtdss logout` → UI 回引导态(M3b D4 已验,此处确认后)再 `mtdss login` 恢复 → **立即**浏览远端/删除/上传。判定:全部即时可用、无卡死(登出已拆 ctrl 连接池,重登录后请求重新打洞,不残留死连接)。
- **H2 devices 现拉(快照陈旧修复)**:home_b 终端重启 dev_b daemon(会话持久化,无需重登)。判定:A 侧 `mtdss devices` 秒级回 `online=true`、UI 树/设备行同步;重启前后浏览同目录内容一致(presence 与目录一致)。注:设备改名端点本里程碑不存在,改名场景不测——本项修的是 devices RPC 现拉(REST 失败回缓存 stale=true)。
- **H3 focus 重拉**:在 MTDSS 窗口外杀/起 dev_b daemon → 点其他窗口再点回 MTDSS 窗口(触发 focus)。判定:树与设备行在线态立即对账(不等推送事件)。
- **H4 StatusBar 加载态**:进入大目录(或对慢设备展开)。判定:状态栏出现「加载中…」段,加载完成消失;失败时显示「加载失败」+ 重试按钮。

## 5. 故障排查速查(M3c 增量)

| 现象 | 先查 |
|---|---|
| put/get 起不来/无卡片 | 本机 daemon 是否新编译且为 §1 重启后的实例(旧实例无 jobs 面);对端是否在线;`--log-file` |
| 托盘 tooltip 不显示「N 个传输中」 | §1 是否已退出全部旧 mtdssd(tooltip 需新 daemon);任务管理器核对 mtdssd 进程数 |
| 粘贴无反应 | 当前位是否目录(设备根卷列表不可粘贴);内部剪贴板是否有条目(dim 视觉);Explorer 复制的内容是否真为文件(CF_HDROP) |
| 冲突对话框没弹 | 同名是否目录对目录(恒合并不弹);是否同设备粘贴/拖拽(device_copy 无对话框,V1);是否 `--conflict` 非 ask |
| 覆盖后出现 `name (1)` | 是否嵌套同名(远端源预扫仅顶层,自动改名安全网,V1 限制) |
| 拖出提示「请拖到桌面…」 | 落点是否库/此电脑/回收站/第三方窗(设计提示非缺陷);普通窗口仍提示则核对窗口是否真资源管理器(非第三方外壳) |
| 第二个并发上传到同一对端失败 | 同一接收方串行收件(V1 限制);~50s Accept 窗口外失败,重试即可 |
| 通知没出现 | 系统勿扰/聚焦助手是否吞掉;被写方 daemon 是否存活;B(无头)无窗内 toast 属预期,以 OS 通知为准 |
| mv 报「跨设备请用 cp」 | mv 仅同设备;跨设备用 `cp`(四态自动分发) |
| 删除确认梯没出现 | 对端是否真不可回收(Windows 回环难构造,A7/G2 记 SKIP 属预期) |
| 登录后远端操作失败 | 对端是否真在线(H1 预期登出→登录后立即可用——ctrl 池已拆、新请求重新打洞);信令是否存活;再失败查 `--log-file` |
